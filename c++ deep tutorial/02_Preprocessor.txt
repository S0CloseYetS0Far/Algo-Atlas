C++ Deep Tutorial — Chapter 2: The Preprocessor

## Chapter Overview

The Preprocessor is the first stage of the C/C++ compilation pipeline. It runs before the compiler
actually starts compiling the source code and handles the preprocessing directives that begin with #.
At its core, the preprocessor is a **pure text substitution engine**: it doesn't understand C++
syntax; it just mechanically performs macro expansion, file inclusion, and conditional compilation.
Understanding how the preprocessor works is essential for writing portable, debuggable C++
code.

This chapter digs into the four-stage compilation process, explains the use of every preprocessing
directive one by one, and uses three real-life scenario case studies to show how the preprocessor is
applied in real projects. It also incorporates the namespace concepts from Chapter 1 to show how the
two work together to organize code.

### Section 1: Basic Example Code + Low-Level Computer Principles

2.1 Basic Examples of Preprocessing Directives
----------------------------------------------

The most commonly used preprocessing directives in C++ are: file inclusion (#include), macro
definition (#define), conditional compilation (#ifdef, #ifndef, #endif), and header guards.

**#include — file inclusion**

```cpp
#include <iostream>     // Include a system header (searches the standard library paths)
#include "myheader.h"   // Include a user header (searches the current directory first, then system paths)
```

The way #include works is extremely simple and blunt: the preprocessor finds the specified file,
**copies and pastes** its entire contents at the location of the #include directive, then carries on. It is purely a text-level operation.

**#define — defining macros**

```cpp
#define PI 3.141592653589793
#define MAX(a, b) ((a) > (b) ? (a) : (b))  // Macro with parameters
#define SQUARE(x) ((x) * (x))               // Note the parentheses!
```

The preprocessor replaces every identifier PI with the text 3.141592653589793, and replaces MAX(3, 5)
with ((3) > (5) ? (3) : (5)). The substitution happens before the compiler parses any C++ syntax.

**Conditional compilation — #ifdef / #ifndef / #endif**

```cpp
#include <iostream>

// Enable debugging via #define
#define DEBUG_MODE

int main() {
#ifdef DEBUG_MODE
    std::cout << "[DEBUG] Program started" << std::endl;
#endif

    std::cout << "Hello, World!" << std::endl;

#ifndef DEBUG_MODE
    std::cout << "This is the release build" << std::endl;
#else
    std::cout << "[DEBUG] This is the debug build" << std::endl;
#endif

    return 0;
}
```

Conditional compilation lets you selectively include or exclude code depending on whether a macro is
defined. In the example above, DEBUG_MODE is defined (#define DEBUG_MODE), so the code inside the
#ifdef block is kept and the code inside the #ifndef block is excluded.

**Header guards — preventing multiple inclusion**

```cpp
// Traditional approach: use #ifndef / #define / #endif
#ifndef MY_HEADER_H
#define MY_HEADER_H

// The header's contents go here
namespace MyLib {
    void doSomething();
    struct Config {
        int width;
        int height;
    };
}

#endif  // MY_HEADER_H
```

When the same header is #included multiple times (for example, A depends on B, C also depends on B,
and the main file #includes both A and C), the first time it is included MY_HEADER_H is not defined,
so the header's contents are kept; on later inclusions MY_HEADER_H is already defined, the #ifndef
condition is false, and everything up to #endif is skipped entirely. This avoids redefinition errors.

```cpp
// The C++ alternative: #pragma once
#pragma once

// Header contents
namespace MyLib {
    void doSomething();
}
```

#pragma once is a non-standard directive supported by almost all mainstream compilers that achieves
the same thing as a header guard. Its semantics are clearer: the current file is included only once
within a translation unit. The advantages of #pragma once are that it is more concise and can't break
because of macro name collisions; the downside is that it is not formally part of the C++ standard
(although in practice it is universally supported).

2.2 The Four Stages of Compilation in Detail
--------------------------------------------

To understand how the preprocessor works, you must first understand the overall C++ compilation
process. A .cpp source file goes through four main stages on its way from source text to an executable:

```
Source files (.cpp / .h)
    │
    ▼
┌─────────────────────────────────────────────────────┐
│   Stage 1: Preprocessing                            │
│   ---------------------------------------           │
│   · Expand all #include (copy-paste file contents)  │
│   · Expand all #define macros (text substitution)   │
│   · Process all conditional directives (#ifdef etc.)│
│   · Remove comments                                 │
│   · Join continued lines (lines ending with \)      │
│   · Output: a clean "translation unit" (pure C++)   │
│   Tool: g++ -E source.cpp -o source.i               │
└───────────────┬─────────────────────────────────────┘
                │  Translation unit (clean C++ source)
                ▼
┌─────────────────────────────────────────────────────┐
│   Stage 2: Compilation                              │
│   ---------------------------------------           │
│   · Lexing: turn the character stream into tokens   │
│   · Parsing: build the abstract syntax tree (AST)   │
│   · Semantic analysis: type checks, overloads, etc. │
│   · IR generation: produce IR (e.g. GCC's GIMPLE)   │
│   · Optimization: various optimization passes       │
│   · Output: assembly code (.s file)                 │
│   Tool: g++ -S source.i -o source.s                 │
└───────────────┬─────────────────────────────────────┘
                │  Assembly code
                ▼
┌─────────────────────────────────────────────────────┐
│   Stage 3: Assembly                                 │
│   ---------------------------------------           │
│   · Translate assembly into machine code (binary)   │
│   · Generate the symbol table                       │
│   · Generate relocation entries                     │
│   · Output: object file (.o / .obj file)            │
│   Tool: g++ -c source.s -o source.o                 │
│         or as source.s -o source.o                  │
└───────────────┬─────────────────────────────────────┘
                │  Object files
                ▼
┌─────────────────────────────────────────────────────┐
│   Stage 4: Linking                                  │
│   ---------------------------------------           │
│   · Merge all object files and libraries            │
│   · Symbol resolution                               │
│   · Address relocation                              │
│   · Output: executable (or dynamic/static library)  │
│   Tool: g++ *.o -o program                          │
│         (internally invokes ld / collect2)          │
└───────────────┬─────────────────────────────────────┘
                │
                ▼
          Executable (ELF/PE/Mach-O)
```

**A deeper look at Stage 1 — preprocessing:**

The core of the preprocessor is a text substitution engine. It maintains a **macro definition table**
(an internal dictionary) recording the currently defined macros and their replacement text. When it
encounters an identifier, the preprocessor looks it up in this table; if it finds a match, it replaces
the identifier with the corresponding text, and if the replacement text itself contains macro identifiers,
they are **expanded recursively** (recursion within macro expansion).

The output of the preprocessing stage is completely "clean" C++ code: no preprocessing directives, no
comments, and all #included file contents "inlined" into the source file. This intermediate file is called
a "translation unit".

Use g++ -E to observe the effect of macro expansion:

Source file test.cpp:
```cpp
#define SQUARE(x) ((x) * (x))
#define DOUBLE(x) (x + x)

int main() {
    int a = SQUARE(3 + 1);      // Expected 16; what do we actually get?
    int b = DOUBLE(3) * DOUBLE(4); // Expected (6) * (8) = 48; what do we actually get?
    int c = SQUARE(DOUBLE(2));  // Nested macro expansion
    return 0;
}
```

Running `g++ -E test.cpp` shows the preprocessor output:

```bash
$ g++ -E test.cpp
```

The code after macro expansion (simplified):

```cpp
int main() {
    int a = ((3 + 1) * (3 + 1));      // SQUARE(3+1) -> ((3+1)*(3+1)) = 16 ✓
    int b = (3 + 3) * (4 + 4);        // DOUBLE(3)*DOUBLE(4) -> (3+3)*(4+4) = 48 ✓
    int c = ((2 + 2) * (2 + 2));      // SQUARE(DOUBLE(2)) -> ((2+2)*(2+2)) = 16 ✓
    return 0;
}
```

Note what happens without parentheses:

```cpp
#define BAD_SQUARE(x) x * x
#define BAD_DOUBLE(x) x + x

// BAD_SQUARE(3+1) expands to 3+1*3+1 = 3+3+1 = 7 (wrong! expected 16)
// BAD_DOUBLE(3)*BAD_DOUBLE(4) expands to 3+3*4+4 = 3+12+4 = 19 (wrong! expected 48)
```

This is why **macro parameters and the entire macro body should be wrapped in parentheses**: the preprocessor
does no arithmetic, only text substitution, so operator precedence is determined entirely by the parentheses in the generated code.

2.3 The Nature of the Preprocessor as a Pure Text Replacer
----------------------------------------------------------

The preprocessor can be thought of as an independent text processor that runs before the compiler. It has
its own "language", the preprocessing directives, which is orthogonal to the C++ language. The preprocessor
does not understand the following C++ concepts:

- **Types**: the preprocessor doesn't know the difference between int and double; all macros are untyped text substitution
- **Scope**: macros have no concept of namespaces or scope; a #define is in effect for the rest of the file (unless
  canceled with #undef)
- **Overloading**: macros cannot be overloaded; each macro name can have only one current definition
- **Templates**: macros are conceptually similar to untyped templates, but without type safety
- **constexpr / consteval**: the preprocessor takes no part in compile-time evaluation

Precisely because macros are untyped and unscoped, the C++ community generally recommends: **whenever possible,
prefer constexpr, const, inline functions, and templates over macros**.

```cpp
// Not recommended: defining constants with macros
#define PI 3.14159

// Recommended: use const or constexpr
constexpr double PI = 3.141592653589793;

// Not recommended: function-like macros
#define MAX(a, b) ((a) > (b) ? (a) : (b))

// Recommended: use a function template (type-safe and overloadable)
template<typename T>
constexpr T max(T a, T b) { return a > b ? a : b; }
```

However, the preprocessor is still irreplaceable in certain scenarios (conditional compilation, header inclusion, source-location macros, etc.).

2.4 How Token Pasting (##) Works
--------------------------------

The Token Pasting operator `##` joins two preprocessing tokens into a single new token. During macro
expansion it acts as "glue", merging two separate tokens into one.

```cpp
#include <iostream>

// Join two tokens with ##
#define CONCAT(a, b) a ## b
// CONCAT(x, 1) -> x1
// CONCAT(my_, var) -> my_var

// Practical use: declare variables in bulk
#define DECLARE_VARIABLE(type, index) type var_##index = index

// Practical use: generate function names
#define MAKE_GETTER(name) \
    int get_##name() const { return name##_; } \
    void set_##name(int val) { name##_ = val; } \
    int name##_

// Practical use: generate unique identifiers
#define UNIQUE_NAME(prefix) prefix ## __LINE__

int main() {
    // Create a variable with CONCAT
    int CONCAT(my, Var) = 42;   // int myVar = 42;
    std::cout << "myVar = " << myVar << std::endl;

    // Use DECLARE_VARIABLE
    DECLARE_VARIABLE(int, 1);   // int var_1 = 1;
    DECLARE_VARIABLE(int, 2);   // int var_2 = 2;
    DECLARE_VARIABLE(int, 3);   // int var_3 = 3;
    std::cout << var_1 << ", " << var_2 << ", " << var_3 << std::endl;

    return 0;
}
```

Key rules of the ## operator:
1. ## may only appear in a macro's replacement list (the macro definition body)
2. Whitespace before and after ## is ignored
3. If the result of the concatenation is not a valid preprocessing token (for example, it forms an invalid identifier),
   the behavior is undefined
4. The ## operator takes precedence over macro expansion: tokens are pasted first, then expanded

```cpp
// A subtlety of ##
#define MACRO_A  1
#define MACRO_B  2
#define JOIN(a, b) a ## b

// JOIN(MACRO_A, MACRO_B)
// Result: MACRO_A+MACRO_B  → not 12!
// Because ## first pastes "MACRO_A"+"MACRO_B" → invalid token, undefined behavior

// The right approach: use two levels of macros
#define JOIN2(a, b) JOIN(a, b)  // Expand the arguments first, then paste
// JOIN2(MACRO_A, MACRO_B) -> JOIN(1, 2) -> 12
```

2.5 How Stringification (#) Works
---------------------------------

The # operator (the stringizing operator) converts a macro argument into a string literal. It puts
double quotes around the macro argument and escapes special characters inside the string.

```cpp
#include <iostream>
#include <string>

// The # operator turns an argument into a string
#define TO_STRING(x) #x

// Combined use: print a variable's name and value
#define PRINT_VAR(var) std::cout << #var << " = " << (var) << std::endl

// Generate a formatted string
#define MAKE_MSG(msg) "Message: " #msg

// Combine with string literals
#define LOG(level, msg) \
    std::cout << "[" #level "] " << msg << std::endl

int main() {
    int count = 42;
    double price = 19.99;

    // Basic use of the # operator
    std::cout << TO_STRING(Hello World) << std::endl;  // "Hello World"

    // PRINT_VAR macro: automatically prints the variable's name and value
    PRINT_VAR(count);    // Output: count = 42
    PRINT_VAR(price);    // Output: price = 19.99

    // MAKE_MSG
    std::string msg = MAKE_MSG(File not found);
    std::cout << msg << std::endl;

    // LOG macro
    LOG(INFO, "Server started on port 8080");
    LOG(ERROR, "Connection refused");
    LOG(WARN, "Low memory");

    // The escaping behavior of #
    std::cout << TO_STRING(He said "Hello") << std::endl;
    // Output: He said \"Hello\"

    return 0;
}
```

Key rules of the # operator:
1. # cannot be preceded by the ## operator
2. Whitespace in the stringized result is collapsed into a single space
3. Special characters in strings (\, "", etc.) are escaped correctly
4. If the argument itself is a macro, it is expanded first and then stringized (depending on the macro expansion order)

Scenarios that combine # and ##:

```cpp
#include <iostream>

// Debugging helper macro: print an expression and its result
#define DEBUG_EXPR(expr) \
    std::cout << "Line " << __LINE__ << ": " #expr " = " << (expr) << std::endl

// Generate enum values and the corresponding string descriptions
#define MAKE_ENUM(name, value) e_##name = value
#define ENUM_STRING(name) #name

namespace Color {
    enum {
        MAKE_ENUM(RED, 0),
        MAKE_ENUM(GREEN, 1),
        MAKE_ENUM(BLUE, 2)
    };
}

int main() {
    int x = 10, y = 5;
    DEBUG_EXPR(x + y);      // Line XX: x + y = 15
    DEBUG_EXPR(x * y - 3);  // Line XX: x * y - 3 = 47

    std::cout << "Color RED: " << ENUM_STRING(RED) << std::endl;
    // Color::e_RED == 0, ENUM_STRING(RED) -> "RED"

    return 0;
}
```

2.6 The Preprocessor's Internal Workflow
----------------------------------------

The preprocessor's internal workflow can be described in the following steps:

**Step 1: Character set mapping**
Physical characters in the source file are mapped to the source character set. Trigraphs (three-character
sequences, removed in C++17) and line continuations (\) are handled (physical lines are joined into logical lines).

**Step 2: Tokenization**
The character stream is split into preprocessing tokens:
- identifiers
- keywords
- literals
- operators and punctuators
- each non-empty sequence of whitespace is replaced with a single space
- comments are replaced with a single space

**Step 3: Executing preprocessing**
Each preprocessing token is processed from left to right:
- On #include: recursively process the included file
- On #define: add the macro to the macro definition table
- On #ifdef / #ifndef: evaluate the condition and decide whether to keep or skip the code section
- On an ordinary identifier: look it up in the macro definition table and expand it if it matches
- On the # and ## operators: perform the corresponding stringification or token pasting

**Step 4: Producing the translation unit**
Output clean C++ code with no preprocessing directives, for use by the compiler's second stage (compilation).

2.7 Observing Preprocessor Output with g++ -E
---------------------------------------------

Let's understand the preprocessing process through a complete experiment. Create the following source file:

```cpp
// experiment.cpp
#define VERSION 2
#define OS "Linux"

#if VERSION >= 2
    #define FEATURE_XYZ
#endif

#ifdef FEATURE_XYZ
    #define LOG(msg) std::cout << "[LOG] " << msg << std::endl
#else
    #define LOG(msg)
#endif

#define CONCAT_HELPER(a, b) a ## b
#define CONCAT(a, b) CONCAT_HELPER(a, b)

int CONCAT(counter, VERSION) = 100;

int main() {
    LOG("Starting on " OS);
    return 0;
}
```

Run the preprocessor:

```bash
$ g++ -E experiment.cpp -o experiment.i
$ cat experiment.i
```

The preprocessed output (experiment.i):

```cpp
# 1 "experiment.cpp"
# 1 "<built-in>"
# 1 "<command-line>"
# 1 "/usr/include/stdc-predef.h" 1 3 4
# 1 "<command-line>" 2
# 1 "experiment.cpp"

int counter2 = 100;

int main() {
    std::cout << "[LOG] " << "Starting on " "Linux" << std::endl;
    return 0;
}
```

Observations:
1. #define VERSION 2 and #define OS "Linux" disappear completely (they were recorded in the macro definition table;
   they only affect later expansions and do not appear in the output themselves)
2. The #if VERSION >= 2 condition is true, so #define FEATURE_XYZ is kept and processed
3. The #ifdef FEATURE_XYZ condition is true, so LOG is defined as a macro with a replacement body
4. CONCAT(counter, VERSION) → CONCAT_HELPER(counter, 2) → counter2
5. LOG("Starting on " OS) → std::cout << "[LOG] " << "Starting on " "Linux"
   (note that adjacent string literals are automatically concatenated by the compiler)
6. The line markers (# 1 "experiment.cpp", etc.) are inserted by the preprocessor so that error messages in later
   compilation stages show the correct source file location

3.1 Defining and Undefining Macros — #define / #undef
-----------------------------------------------------

**Basic macro definitions (no parameters)**

```cpp
#define PI 3.141592653589793
#define BUFFER_SIZE 4096
#define APP_NAME "MyApplication"
#define CONFIG_FILE_PATH "/etc/myapp/config.ini"
```

Use cases:
- Defining compile-time constants
- Defining platform-specific constants
- Defining configuration information
- Replacing magic numbers in code

**Undefining a macro**

```cpp
#define TEMP 100

// Use TEMP...

#undef TEMP  // Remove the definition of TEMP

// From here on, TEMP is no longer a macro
// If TEMP is later #defined again as 200, TEMP is redefined as 200
```

```cpp
#include <iostream>

int main() {
    #define VALUE 10
    std::cout << "VALUE = " << VALUE << std::endl;  // 10

    #undef VALUE
    #define VALUE 20
    std::cout << "VALUE = " << VALUE << std::endl;  // 20

    // std::cout << VALUE << std::endl;  // If it had been #undef'd and not redefined, this would be a compile error

    return 0;
}
```

**Macros with parameters**

```cpp
// Basic form
#define ADD(x, y) ((x) + (y))
#define MAX(x, y) ((x) > (y) ? (x) : (y))
#define IS_UPPER(c) ((c) >= 'A' && (c) <= 'Z')

// Multiple parameters
#define CLAMP(val, lo, hi) ((val) < (lo) ? (lo) : ((val) > (hi) ? (hi) : (val)))

// Type conversion (note: no type safety)
#define TO_INT(x)  ((int)(x))
#define TO_FLOAT(x) ((float)(x))

// Multi-statement macro body (wrapping it in do { ... } while(0) is a classic trick)
#define SWAP(a, b) do { \
    auto temp = (a);    \
    (a) = (b);          \
    (b) = temp;         \
} while(0)

#include <iostream>

int main() {
    int a = 10, b = 20;
    SWAP(a, b);
    std::cout << "a = " << a << ", b = " << b << std::endl;  // a=20, b=10

    // If SWAP didn't use do-while(0), the following code would break:
    // if (a > b) SWAP(a, b); else a = 0;
    // It would expand to: if (a > b) { auto temp = a; a = b; b = temp; }; else a = 0;
    // Note the trailing semicolon, which leaves the else without a matching if (the dangling-else problem)
    // do-while(0) requires a trailing semicolon, which solves this problem perfectly

    if (a > b)
        SWAP(a, b);
    else
        a = 0;

    return 0;
}
```

**Variadic Macros (C++11)**

```cpp
#include <iostream>

// Use ... and __VA_ARGS__
#define LOG(fmt, ...) printf(fmt, __VA_ARGS__)

// The empty-argument case (GCC/Clang extension ##__VA_ARGS__)
#define DEBUG_LOG(fmt, ...) \
    fprintf(stderr, "[DEBUG] %s:%d: " fmt "\n", __FILE__, __LINE__, ##__VA_ARGS__)

// C++20 __VA_OPT__ handles optional arguments more safely
// #define LOG2(fmt, ...) std::printf(fmt __VA_OPT__(,) __VA_ARGS__)

int main() {
    LOG("Value: %d\n", 42);
    DEBUG_LOG("Starting %s v%d", "MyApp", 1);  // With arguments
    // DEBUG_LOG("Server started"); // Under GCC, ##__VA_ARGS__ handles empty arguments correctly
    return 0;
}
```

`##__VA_ARGS__` is a GCC/Clang extension: when the variadic argument list is empty, it removes the preceding comma.
C++20 introduced the standard `__VA_OPT__` to handle this problem.

3.2 Conditional Compilation — #if / #ifdef / #ifndef / #else / #elif / #endif / defined()
-----------------------------------------------------------------------------------------

**#ifdef and #ifndef — checking whether a macro is defined**

```cpp
#define FEATURE_LOGGING

#ifdef FEATURE_LOGGING
    #define LOG(x) std::cout << x << std::endl
#else
    #define LOG(x)  // Empty macro that does nothing
#endif

#ifndef MAX_CONNECTIONS
    #define MAX_CONNECTIONS 100  // Provide a default value if it isn't defined
#endif
```

**#if — evaluating constant expressions**

```cpp
#if defined(CONFIG_A) && CONFIG_A >= 2
    // CONFIG_A must be defined and have a value >= 2
#endif

#if __cplusplus >= 201703L
    // C++17 and above
    #define HAVE_CPP17 1
#endif

#if defined(__GNUC__) && !defined(__clang__)
    // Compiled only under GCC (not Clang)
    #define COMPILER_NAME "GCC"
#elif defined(__clang__)
    #define COMPILER_NAME "Clang"
#elif defined(_MSC_VER)
    #define COMPILER_NAME "MSVC"
#else
    #define COMPILER_NAME "Unknown"
#endif
```

**The defined() operator**

```cpp
// The defined() operator returns 1 or 0, indicating whether a macro is defined
#if defined(DEBUG) && !defined(NDEBUG)
    // In debug mode, and NDEBUG is not defined
#endif

// Difference from #ifdef: defined() can combine multiple conditions
#if defined(FEATURE_A) || defined(FEATURE_B)
    // At least one of A or B is enabled
#endif
```

**Complete example: compiling different code depending on configuration**

```cpp
#include <iostream>

// Simulated build configuration
#define USE_OPENGL
#define GRAPHICS_QUALITY 2

#if defined(USE_OPENGL) && defined(USE_VULKAN)
    #error "OpenGL and Vulkan cannot both be enabled!"
#endif

#ifdef USE_OPENGL
    #define RENDER_BACKEND "OpenGL"
    void render() { std::cout << "Rendering with OpenGL" << std::endl; }
#elif defined(USE_VULKAN)
    #define RENDER_BACKEND "Vulkan"
    void render() { std::cout << "Rendering with Vulkan" << std::endl; }
#else
    #define RENDER_BACKEND "Software"
    void render() { std::cout << "Rendering with Software" << std::endl; }
#endif

#if GRAPHICS_QUALITY >= 3
    #define TEXTURE_SIZE 4096
    #define SHADOW_QUALITY "High"
#elif GRAPHICS_QUALITY >= 2
    #define TEXTURE_SIZE 2048
    #define SHADOW_QUALITY "Medium"
#elif GRAPHICS_QUALITY >= 1
    #define TEXTURE_SIZE 1024
    #define SHADOW_QUALITY "Low"
#else
    #define TEXTURE_SIZE 512
    #define SHADOW_QUALITY "Minimal"
#endif

int main() {
    std::cout << "Backend: " << RENDER_BACKEND << std::endl;
    std::cout << "Texture: " << TEXTURE_SIZE << std::endl;
    std::cout << "Shadows: " << SHADOW_QUALITY << std::endl;
    render();
    return 0;
}
```

3.3 File Inclusion — #include / Header Guards / #pragma once
------------------------------------------------------------

**The two forms of #include**

```cpp
#include <iostream>     // Angle brackets: search the standard system header paths
#include "myheader.h"   // Double quotes: search the current file's directory first, then the system paths
#include "../lib/utils.h" // Relative paths work too
```

**The standard way to write an Include Guard**

```cpp
// mylibrary.h
#ifndef MYLIBRARY_H        // Check whether the macro is undefined
#define MYLIBRARY_H        // Define it immediately to prevent multiple inclusion

// ... header contents ...

#endif                     // MYLIBRARY_H
```

**#pragma once**

```cpp
#pragma once

// Header contents
// The compiler guarantees this file is processed only once in the current translation unit
```

Here is how the two compare:

| Feature | #ifndef/#define/#endif | #pragma once |
|---------|------------------------|--------------|
| Standardization | C++ standard | Non-standard (but widely supported) |
| Uniqueness guarantee | Depends on the macro name (may collide) | Depends on the file path (more reliable) |
| Compilation speed | Slightly slower (file must be opened to check the macro) | Slightly faster (tracked internally by the compiler) |
| Symbolic link handling | By macro name | Implementation-dependent |
| Forward declaration support | Manual forward declarations | Also manual |

The combination recommended in practice:

```cpp
#pragma once
#ifndef MYCOMPLEXHEADER_H
#define MYCOMPLEXHEADER_H

// Use both at the same time:
// #pragma once provides fast, compiler-level skipping
// #ifndef provides standard compliance as a fallback

// ... header contents ...

#endif
```

3.4 Special Operators — # and ##
--------------------------------

**The # operator — stringification**

```cpp
#define STRINGIFY(x) #x
#define TO_STRING_WITH_FILE(var) "File: " __FILE__ ", Variable: " #var

// #@ converts a character into a character literal (MSVC extension, non-standard)
// #define CHARIFY(c) #@c

const char* name = STRINGIFY(Hello World);  // "Hello World"
const char* desc = STRINGIFY(42);           // "42"
// Note: STRINGIFY(42 + 10) -> "42 + 10" (the expression itself is stringized, not the result)
```

**The ## operator — token pasting**

```cpp
#define GLUE(a, b) a ## b

// Arguments need to be expanded first; otherwise macro identifiers themselves are not expanded
#define GLUE2(a, b) GLUE(a, b)

// For generating unique variable names
#define UNIQUE_VAR(prefix) GLUE(prefix, __COUNTER__) // __COUNTER__ is a GCC extension

// For generating class method names
#define PROPERTY(type, name) \
    type GLUE(_, name); \
    type GLUE(get_, name)() const { return GLUE(_, name); } \
    void GLUE(set_, name)(type val) { GLUE(_, name) = val; }
```

```cpp
    // Linux platform
```

**#line — changing the line number and file name**

3.7 Header Include Search Paths

Understanding the #include search strategy matters for build systems:

```bash

#    The directory of the current file is not searched
```

3.8 Special Rules of Macro Expansion
------------------------------------

**Suppression of recursive expansion**
If a macro encounters itself again during its own expansion, the preprocessor does not expand it a second time (preventing infinite recursion):

```cpp
#define FOO BAR
#define BAR FOO

// FOO → BAR → FOO  (the second FOO is not expanded again)
// The final result is FOO (as an ordinary identifier)
```

**Expansion order rules**
1. First, scan the replacement text for the # and ## operators
2. Then expand macros in the arguments (argument expansion)
3. Finally, expand macros in the replacement text (body expansion)
4. Repeat steps 2-3 recursively until no new expansions can occur

```cpp
#include <iostream>

#define A 1
#define B 2
#define CONCAT_A_B(x, y) x ## y
#define CONCAT(x, y) CONCAT_A_B(x, y)

int main() {
    int value_1_2 = 100;
    int result = CONCAT(value_, CONCAT(A, B));
    // Expansion: CONCAT(value_, CONCAT(1, 2))
    //     -> CONCAT(value_, CONCAT_A_B(1, 2))
    //     -> CONCAT(value_, 12)
    //     -> CONCAT_A_B(value_, 12)
    //     -> value_12  (but what we wanted was value_1_2!)

    // The right approach: recognize that A and B are already values; you can't use ## to "compute" their sum
    // A different macro structure needs to be designed

    std::cout << result << std::endl;
    return 0;
}
```

3.9 Using Macros Across Files
-----------------------------

A macro is only in effect within the translation unit where it is defined. To make a macro available in multiple source files, it must be defined in a header file:

Case 1: Debug Logging System
----------------------------------------------------------------

Real-life scenario: we are developing the backend service for a mobile app. During development and debugging
we need detailed logs, but when releasing to users we turn logging off to reduce performance overhead. The
system must support different log levels (DEBUG/INFO/WARN/ERROR), and every log entry must automatically include the file name and line number.

This case covers: variadic macros, __FILE__/__LINE__, conditional compilation as a feature switch, and organizing
code with namespaces (bringing in Chapter 1 knowledge).

```cpp
#include <iostream>
#include <string>
#include <ctime>
#include <cstdarg>

// ============================================================
// Logging configuration (controlled at compile time)
// Comment out the line below to turn off debug logging globally
#define ENABLE_LOGGING

// Set the log level: 0=ALL, 1=INFO+, 2=WARN+, 3=ERROR+
#define LOG_LEVEL 0

// ============================================================
// Logging system namespace
// ============================================================
namespace Logger {

    // Get the current time as a string
    // (<chrono> from Chapter 6 would be better; <ctime> is used here for a simplified demo)
    namespace {
        std::string getTimestamp() {
            std::time_t now = std::time(nullptr);
            char buffer[32];
            std::strftime(buffer, sizeof(buffer),
                          "%Y-%m-%d %H:%M:%S",
                          std::localtime(&now));
            return std::string(buffer);
        }
    }

    // Log level enum
    enum Level {
        DEBUG = 0,
        INFO  = 1,
        WARN  = 2,
        ERROR = 3
    };

    // Get the name of a log level
    inline const char* levelToString(Level lv) {
        switch (lv) {
            case DEBUG: return "DEBUG";
            case INFO:  return "INFO ";
            case WARN:  return "WARN ";
            case ERROR: return "ERROR";
            default:    return "UNKN ";
        }
    }

    // Low-level print function
    inline void logPrint(Level lv, const char* file, int line,
                         const char* fmt, ...) {
        char buffer[1024];

        va_list args;
        va_start(args, fmt);
        std::vsnprintf(buffer, sizeof(buffer), fmt, args);
        va_end(args);

        std::cout << "[" << getTimestamp() << "] "
                  << "[" << levelToString(lv) << "] "
                  << "[" << file << ":" << line << "] "
                  << buffer << std::endl;
    }

}  // namespace Logger

// ============================================================
// Logging macro definitions — the convenient public interface
// ============================================================

#ifdef ENABLE_LOGGING

    // Debug log: output only when LOG_LEVEL == 0
    #if LOG_LEVEL <= 0
        #define LOG_DEBUG(fmt, ...) \
            Logger::logPrint(Logger::DEBUG, __FILE__, __LINE__, \
                             fmt, ##__VA_ARGS__)
    #else
        #define LOG_DEBUG(fmt, ...) ((void)0)
    #endif

    // Info log: output when LOG_LEVEL <= 1
    #if LOG_LEVEL <= 1
        #define LOG_INFO(fmt, ...) \
            Logger::logPrint(Logger::INFO, __FILE__, __LINE__, \
                             fmt, ##__VA_ARGS__)
    #else
        #define LOG_INFO(fmt, ...) ((void)0)
    #endif

    // Warning log: output when LOG_LEVEL <= 2
    #if LOG_LEVEL <= 2
        #define LOG_WARN(fmt, ...) \
            Logger::logPrint(Logger::WARN, __FILE__, __LINE__, \
                             fmt, ##__VA_ARGS__)
    #else
        #define LOG_WARN(fmt, ...) ((void)0)
    #endif

    // Error log: always output (LOG_LEVEL <= 3)
    #if LOG_LEVEL <= 3
        #define LOG_ERROR(fmt, ...) \
            Logger::logPrint(Logger::ERROR, __FILE__, __LINE__, \
                             fmt, ##__VA_ARGS__)
    #else
        #define LOG_ERROR(fmt, ...) ((void)0)
    #endif

#else
    // Logging completely disabled: all macros expand to no-ops
    #define LOG_DEBUG(fmt, ...) ((void)0)
    #define LOG_INFO(fmt, ...)  ((void)0)
    #define LOG_WARN(fmt, ...)  ((void)0)
    #define LOG_ERROR(fmt, ...) ((void)0)
#endif

// ============================================================
// Simulated app backend service
// ============================================================
namespace AppServer {

    namespace UserService {
        bool authenticateUser(const std::string& username,
                              const std::string& password) {
            LOG_DEBUG("Starting authentication for user: %s", username.c_str());

            // Simulate a database query
            if (password.length() < 6) {
                LOG_WARN("Password for user %s is too short (length: %zu)",
                         username.c_str(), password.length());
                return false;
            }

            LOG_INFO("User %s authenticated successfully", username.c_str());
            return true;
        }
    }

    namespace Database {
        bool connect(const std::string& host, int port) {
            LOG_INFO("Connecting to database %s:%d", host.c_str(), port);

            // Simulate the connection process
            if (port < 1024) {
                LOG_WARN("Database port %d may require administrator privileges", port);
            }

            LOG_DEBUG("Database connection established: %s:%d", host.c_str(), port);
            return true;
        }

        bool disconnect() {
            LOG_INFO("Disconnecting from database");
            return true;
        }
    }

    namespace PaymentProcessor {
        bool processPayment(const std::string& orderId, double amount) {
            LOG_INFO("Processing payment: order=%s, amount=%.2f",
                     orderId.c_str(), amount);

            if (amount <= 0) {
                LOG_ERROR("Invalid payment amount: %.2f (order=%s)",
                          amount, orderId.c_str());
                return false;
            }

            if (amount > 10000) {
                LOG_WARN("Large payment: %.2f (order=%s), additional review required",
                         amount, orderId.c_str());
            }

            LOG_DEBUG("Payment completed: order=%s", orderId.c_str());
            return true;
        }
    }

}  // namespace AppServer

int main() {
    // You can switch the log level at compile time:
    // change #define LOG_LEVEL to 1/2/3 or comment out #define ENABLE_LOGGING

    std::cout << "==== Application server starting ====" << std::endl;

    // Simplify with a using directive
    using namespace AppServer;

    // Database operations
    Database::connect("localhost", 3306);

    // User authentication
    UserService::authenticateUser("alice", "12345");   // Password too short
    UserService::authenticateUser("bob", "secureP@ss");  // Authentication succeeds

    // Payment processing
    PaymentProcessor::processPayment("ORD-001", 99.99);
    PaymentProcessor::processPayment("ORD-002", -5.00);  // Invalid
    PaymentProcessor::processPayment("ORD-003", 15000.00); // Large amount

    Database::disconnect();

    std::cout << "==== Server shut down ====" << std::endl;
    return 0;
}
```

Code walkthrough:
- The `Logger` namespace encapsulates the low-level implementation of log output
- The `ENABLE_LOGGING` macro is the master switch for logging
- The `LOG_LEVEL` macro controls the minimum log level that is output
- The four macros such as `LOG_DEBUG` automatically carry __FILE__ and __LINE__, making it easy to locate code quickly while debugging
- `##__VA_ARGS__` (a GCC extension) handles the case where the variadic arguments are empty
- When logging is disabled, all macros expand to `((void)0)`, incurring no runtime overhead


Case 2: Cross-Platform File Path Handler
----------------------------------------------------------------

Real-life scenario: we are developing a file manager app that must join file paths correctly on both
Windows and Linux. Windows uses the backslash `\`, while Linux uses the forward slash `/`. It also has to choose
different system APIs depending on the platform.

This case covers: conditional compilation (#ifdef), platform detection macros, and cross-platform abstraction with function-like macros.

```cpp
#include <iostream>
#include <string>
#include <vector>

// ============================================================
// Platform detection and configuration
// ============================================================
#ifdef _WIN32
    #define PLATFORM_NAME "Windows"
    #define PATH_SEPARATOR '\\'
    #define PATH_SEPARATOR_STR "\\"
    #define NEWLINE "\r\n"
    #define DRIVE_SEPARATOR ':'
#elif defined(__APPLE__) && defined(__MACH__)
    #define PLATFORM_NAME "macOS"
    #define PATH_SEPARATOR '/'
    #define PATH_SEPARATOR_STR "/"
    #define NEWLINE "\n"
    #define DRIVE_SEPARATOR 0
#else
    #define PLATFORM_NAME "Linux"
    #define PATH_SEPARATOR '/'
    #define PATH_SEPARATOR_STR "/"
    #define NEWLINE "\n"
    #define DRIVE_SEPARATOR 0
#endif

// Platform-specific API macros
#ifdef _WIN32
    #define PLATFORM_CREATE_DIR(path) \
        std::cout << "[WinAPI] CreateDirectory(" << path << ")" << std::endl
    #define PLATFORM_DELETE_FILE(path) \
        std::cout << "[WinAPI] DeleteFile(" << path << ")" << std::endl
    #define PLATFORM_GET_HOME() \
        std::string(std::getenv("USERPROFILE") ? std::getenv("USERPROFILE") : "C:\\Users\\Default")
#else
    #define PLATFORM_CREATE_DIR(path) \
        std::cout << "[POSIX] mkdir(" << path << ", 0755)" << std::endl
    #define PLATFORM_DELETE_FILE(path) \
        std::cout << "[POSIX] unlink(" << path << ")" << std::endl
    #define PLATFORM_GET_HOME() \
        std::string(std::getenv("HOME") ? std::getenv("HOME") : "/home/default")
#endif

// ============================================================
// File path handling namespace
// ============================================================
namespace PathUtils {

    // Check whether a path is absolute
    bool isAbsolute(const std::string& path) {
        if (path.empty()) return false;
    #ifdef _WIN32
        // Windows: C:\xxx or \\server\share
        return (path.length() >= 2 && path[1] == ':') ||
               (path.length() >= 2 && path[0] == '\\' && path[1] == '\\');
    #else
        // Linux/macOS: /xxx
        return path[0] == '/';
    #endif
    }

    // Join paths
    std::string join(const std::string& base, const std::string& sub) {
        if (base.empty()) return sub;
        if (sub.empty()) return base;

        // Check whether base ends with a separator
        bool baseEnds = (base.back() == PATH_SEPARATOR);
        bool subStarts = (sub.front() == PATH_SEPARATOR);

        if (baseEnds && subStarts) {
            return base + sub.substr(1);  // Drop the separator at the start of sub
        } else if (!baseEnds && !subStarts) {
            return base + PATH_SEPARATOR + sub;
        } else {
            return base + sub;
        }
    }

    // Join multiple path segments (simulating a variadic macro)
    std::string joinMany(std::initializer_list<std::string> parts) {
        std::string result;
        for (const auto& part : parts) {
            result = join(result, part);
        }
        return result;
    }

    // Get the parent directory of a path
    std::string parentDir(const std::string& path) {
        if (path.empty()) return ".";
        auto pos = path.find_last_of(PATH_SEPARATOR);
        if (pos == std::string::npos) return ".";
        if (pos == 0) return std::string(1, PATH_SEPARATOR);  // Root directory
        return path.substr(0, pos);
    }

    // Get the file name part
    std::string fileName(const std::string& path) {
        if (path.empty()) return "";
        auto pos = path.find_last_of(PATH_SEPARATOR);
        if (pos == std::string::npos) return path;
        return path.substr(pos + 1);
    }

    // Get the extension
    std::string extension(const std::string& path) {
        std::string fname = fileName(path);
        auto pos = fname.find_last_of('.');
        if (pos == std::string::npos) return "";
        return fname.substr(pos);
    }

}  // namespace PathUtils

// ============================================================
// Macro: join paths in bulk (uses # and ## to generate debug info)
// ============================================================
#define JOIN_PATH_DEBUG(base, sub) \
    (std::cout << "[Join] " #base " + " #sub " = ", \
     PathUtils::join(base, sub))

// ============================================================
// Simulated file manager
// ============================================================
namespace FileManager {

    namespace Config {
        // Default working directory
        std::string getDefaultPath() {
            std::string home = PLATFORM_GET_HOME();
            return PathUtils::join(home, "Documents");
        }
    }

    // Create a directory tree
    void createDirectoryTree(const std::string& root) {
        std::cout << "\nCreating directory tree under " << root << ":" << std::endl;

        std::vector<std::string> subdirs = {
            "Projects", "Downloads", "Pictures", "Music", "Videos"
        };

        for (const auto& dir : subdirs) {
            std::string fullPath = PathUtils::join(root, dir);
            PLATFORM_CREATE_DIR(fullPath);
        }
    }

    // Show path information
    void showPathInfo(const std::string& path) {
        std::cout << "\n--- Path info ---" << std::endl;
        std::cout << "Full path: " << path << std::endl;
        std::cout << "Platform: " << PLATFORM_NAME << std::endl;
        std::cout << "Separator: " << PATH_SEPARATOR_STR << std::endl;
        std::cout << "Absolute path: "
                  << (PathUtils::isAbsolute(path) ? "yes" : "no") << std::endl;
        std::cout << "Parent directory: " << PathUtils::parentDir(path) << std::endl;
        std::cout << "File name: " << PathUtils::fileName(path) << std::endl;
        std::cout << "Extension: " << PathUtils::extension(path) << std::endl;
    }

}  // namespace FileManager

int main() {
    std::cout << "╔══════════════════════════════╗" << std::endl;
    std::cout << "║         File Manager         ║" << std::endl;
    std::cout << "╚══════════════════════════════╝\n" << std::endl;

    std::cout << "Running on: " << PLATFORM_NAME << std::endl;
    std::cout << "Path separator: '" << PATH_SEPARATOR_STR << "'" << std::endl;

    // Show the HOME directory
    std::string home = PLATFORM_GET_HOME();
    std::cout << "User directory: " << home << std::endl;

    // Join paths
    std::string docsDir = FileManager::Config::getDefaultPath();
    std::cout << "Documents directory: " << docsDir << std::endl;

    // Join with the macro and print debug info
    std::string projectDir = JOIN_PATH_DEBUG(docsDir, "Projects");
    std::string sourceFile = PathUtils::join(projectDir, "main.cpp");

    // Join multiple path segments
    std::string deepPath = PathUtils::joinMany(
        {home, "Projects", "MyApp", "src", "core", "engine.cpp"});
    std::cout << "\nDeep path: " << deepPath << std::endl;

    // Show path information
    FileManager::showPathInfo(deepPath);

    // Simulate creating directories
    FileManager::createDirectoryTree(docsDir);

    // Simulate deleting a file
    PLATFORM_DELETE_FILE(PathUtils::join(docsDir, "temp.txt"));

    return 0;
}
```

Code walkthrough:
- `#ifdef _WIN32` automatically detects the platform at compile time and defines the corresponding path separator, API macros, etc.
- The `PLATFORM_CREATE_DIR` macro expands to API call code for the respective platform
- The `PathUtils` namespace encapsulates cross-platform path handling functions
- The `JOIN_PATH_DEBUG` macro uses the `#` operator to print debug info showing the paths before and after joining
- Compiled on Windows and on Linux, the program behaves differently, yet the source code is exactly the same


Case 3: Game Engine Configuration System
----------------------------------------------------------------

Real-life scenario: a game engine needs to be configured differently at compile time depending on the target platform
(PC/mobile/console), including choosing the precision of the math library, whether to enable 3D rendering, the debug
level, and so on. It also needs macros for common math constants, and uses the # and ## operators to generate debug strings automatically.

This case brings in: namespaces (Chapter 1) to organize different modules, macro definitions, conditional compilation, and the #/## operators.

```cpp
#include <iostream>
#include <string>
#include <cmath>

// ============================================================
// Compile-time configuration
// ============================================================

// Target platform: 0=PC, 1=Mobile, 2=Console
#define TARGET_PLATFORM 0

// Precision: 0=float (single precision), 1=double (double precision)
#define PRECISION_MODE 0

// Feature switches
#define ENABLE_3D_RENDERING
#define ENABLE_PHYSICS
// #define ENABLE_VR      // Comment out to disable VR support

// Debug level: 0=None, 1=Basic, 2=Verbose
#define DEBUG_LEVEL 2

// ============================================================
// Choose configuration based on the platform
// ============================================================
#if TARGET_PLATFORM == 0
    // PC
    #define PLATFORM_TAG "PC"
    #define MAX_TEXTURE_SIZE 4096
    #define MAX_FPS 144
    #define SUPPORT_KEYBOARD_MOUSE
#elif TARGET_PLATFORM == 1
    // Mobile
    #define PLATFORM_TAG "Mobile"
    #define MAX_TEXTURE_SIZE 1024
    #define MAX_FPS 60
    #define SUPPORT_TOUCH
#elif TARGET_PLATFORM == 2
    // Game console
    #define PLATFORM_TAG "Console"
    #define MAX_TEXTURE_SIZE 2048
    #define MAX_FPS 60
    #define SUPPORT_GAMEPAD
#endif

// ============================================================
// Choose the numeric type based on precision
// ============================================================
#if PRECISION_MODE == 0
    using Real = float;
    #define REAL_TAG "float"
    #define REAL_EPSILON 1.192092896e-07f
#else
```

Exercise: Application Configuration Manager
-------------------------------------------

**Scenario description**:
Write an application configuration manager that can switch between DEBUG and RELEASE modes at compile time and
output different debug logs depending on the mode. Also use a standard header guard in the header file.

**Requirements**:

1. **Define a CONFIG_MODE macro**:
   - A value of 0 means RELEASE mode
   - A value of 1 means DEBUG mode
   - In DEBUG mode, every configuration read must automatically output a debug log (including the file name and line number)

2. **Header guard**:
   - Create `app_config.h` (or simply simulate it in a single file) and use `#ifndef / #define / #endif`
     to implement the header guard
   - Additionally add `#pragma once` as a second layer of protection

3. **Define APP_VERSION-related macros**:
   - Three numeric macros: `APP_VERSION_MAJOR`, `APP_VERSION_MINOR`, `APP_VERSION_PATCH`
   - Use the `#` operator to combine the version number into a string in "major.minor.patch" format

4. **Use C++ version features via conditional compilation**:
   - Check the value of `__cplusplus`
   - For C++17 and above, use `std::optional` to return configuration values
   - Below C++17, use pointers (returning nullptr means not found)
   - Use conditional compilation to choose the corresponding implementation

5. **Implement the ConfigManager namespace**:
   - Provide three configuration read functions: `getString(key)`, `getInt(key)`, `getBool(key)`
   - Store configuration entries in an internal `std::map`
   - In DEBUG mode, output a log on every configuration read
   - In RELEASE mode, read silently

6. **Main function demo**:
   - Read several configuration entries
   - Show the different behavior in DEBUG and RELEASE modes (recompile after changing the macro)

**Reference solution skeleton**:

```cpp
#include <iostream>
#include <string>
#include <map>

// ============================================================
// Header guard (simulating app_config.h)
// ============================================================
#ifndef APP_CONFIG_H
#define APP_CONFIG_H
#pragma once

// Build mode: 0 = RELEASE, 1 = DEBUG
#define CONFIG_MODE 1

// Version number
#define APP_VERSION_MAJOR 2
#define APP_VERSION_MINOR 1
#define APP_VERSION_PATCH 5

// Convert the version number into a string
#define STRINGIFY_HELPER(x) #x
#define STRINGIFY(x) STRINGIFY_HELPER(x)
#define APP_VERSION_STRING \
    STRINGIFY(APP_VERSION_MAJOR) "." \
    STRINGIFY(APP_VERSION_MINOR) "." \
    STRINGIFY(APP_VERSION_PATCH)

// ============================================================
// Debug logging macro
// ============================================================
#if CONFIG_MODE == 1
    #define CONFIG_LOG(msg) \
        std::cout << "[DEBUG-CONFIG][" << __FILE__ << ":" << __LINE__ \
                  << "] " << msg << std::endl
#else
    #define CONFIG_LOG(msg) ((void)0)
#endif

// ============================================================
// Conditional compilation based on C++ version
// ============================================================
#if __cplusplus >= 201703L
    #include <optional>
    #define OPTIONAL_RETURN(type) std::optional<type>
    #define NO_VALUE std::nullopt
    #define UNWRAP_OR(opt, default_val) (opt.value_or(default_val))
#else
    #define OPTIONAL_RETURN(type) type*
    #define NO_VALUE nullptr
    #define UNWRAP_OR(opt, default_val) ((opt) ? *(opt) : (default_val))
#endif

#endif  // APP_CONFIG_H

// ============================================================
// Configuration manager namespace
// ============================================================
namespace ConfigManager {

    namespace {
        // Internal configuration storage
        std::map<std::string, std::string> configStore;

        // Initialize the default configuration
        struct ConfigInitializer {
            ConfigInitializer() {
                configStore["app.name"] = "MySuperApp";
                configStore["app.version"] = APP_VERSION_STRING;
                configStore["server.host"] = "localhost";
                configStore["server.port"] = "8080";
                configStore["feature.ai"] = "true";
                configStore["feature.logging"] = "true";
                configStore["cache.size_mb"] = "256";
                configStore["max_connections"] = "100";
                configStore["timeout_seconds"] = "30";
                configStore["debug.enabled"] = (CONFIG_MODE == 1) ? "true" : "false";
            }
        };
        ConfigInitializer init;  // Static initialization
    }  // anonymous namespace

    // Get a string configuration value
    OPTIONAL_RETURN(std::string) getString(const std::string& key) {
        CONFIG_LOG("Reading string config: " << key);
        auto it = configStore.find(key);
        if (it != configStore.end()) {
            CONFIG_LOG("  Value: " << it->second);
            return it->second;
        }
        CONFIG_LOG("  Config entry does not exist: " << key);
        return NO_VALUE;
    }

    // Get an integer configuration value
    OPTIONAL_RETURN(int) getInt(const std::string& key) {
        CONFIG_LOG("Reading integer config: " << key);
        auto it = configStore.find(key);
        if (it != configStore.end()) {
            int value = std::stoi(it->second);
            CONFIG_LOG("  Value: " << value);
            return value;
        }
        CONFIG_LOG("  Config entry does not exist: " << key);
        return NO_VALUE;
    }

    // Get a boolean configuration value
    OPTIONAL_RETURN(bool) getBool(const std::string& key) {
        CONFIG_LOG("Reading boolean config: " << key);
        auto it = configStore.find(key);
        if (it != configStore.end()) {
            bool value = (it->second == "true" || it->second == "1");
            CONFIG_LOG("  Value: " << (value ? "true" : "false"));
            return value;
        }
        CONFIG_LOG("  Config entry does not exist: " << key);
        return NO_VALUE;
    }

    // List all configuration entries
    void listAll() {
        std::cout << "\n=== All configuration entries ===" << std::endl;
        for (const auto& pair : configStore) {
            std::cout << "  " << pair.first << " = " << pair.second << std::endl;
        }
    }
}  // namespace ConfigManager

int main() {
    std::cout << "╔══════════════════════════════╗" << std::endl;
    std::cout << "║  App Configuration Manager   ║" << std::endl;
    std::cout << "╚══════════════════════════════╝\n" << std::endl;

    std::cout << "Build mode: "
              << (CONFIG_MODE == 1 ? "DEBUG" : "RELEASE") << std::endl;
    std::cout << "Version: " << APP_VERSION_STRING << std::endl;

#ifdef __cplusplus
    std::cout << "C++ standard: " << __cplusplus << std::endl;
#endif

#if __cplusplus >= 201703L
    std::cout << "Using C++17 feature: std::optional" << std::endl;
#else
    std::cout << "Using the traditional approach: pointer return values" << std::endl;
#endif

    ConfigManager::listAll();

    std::cout << "\n=== Reading configuration ===" << std::endl;

    // Read existing configuration entries
    auto serverHost = ConfigManager::getString("server.host");
    auto serverPort = ConfigManager::getInt("server.port");
    auto cacheSize = ConfigManager::getInt("cache.size_mb");
    auto aiEnabled = ConfigManager::getBool("feature.ai");
    auto debugEnabled = ConfigManager::getBool("debug.enabled");

    std::cout << "\n=== Results ===" << std::endl;
    std::cout << "Server: "
              << UNWRAP_OR(serverHost, std::string("unknown"))
              << ":" << UNWRAP_OR(serverPort, 80) << std::endl;
    std::cout << "Cache size: "
              << UNWRAP_OR(cacheSize, 128) << " MB" << std::endl;
    std::cout << "AI feature: "
              << (UNWRAP_OR(aiEnabled, false) ? "enabled" : "disabled") << std::endl;
    std::cout << "Debug: "
              << (UNWRAP_OR(debugEnabled, false) ? "enabled" : "disabled") << std::endl;

    // Read a configuration entry that doesn't exist
    auto unknown = ConfigManager::getString("nonexistent.key");
    std::cout << "Unknown config entry: "
              << UNWRAP_OR(unknown, std::string("<not found>")) << std::endl;

    return 0;
}
```

**Key points assessed**:
- Practical use of conditional compilation (#if / #ifdef)

- Using the # operator to turn version number macros into a string
- Conditionally compiling different implementations depending on the value of __cplusplus
- Different macro behavior in DEBUG/RELEASE modes
- Applying variadic macros to logging

5.1 Pitfalls and Advanced Techniques of Macro Expansion
-------------------------------------------------------

**Pitfall 1: Macro arguments evaluated multiple times**

```cpp
#include <iostream>

#define SQUARE(x) ((x) * (x))

int getValue() {
    static int counter = 0;
    std::cout << "getValue() call #" << (++counter) << std::endl;
    return counter;
}

int main() {
    // SQUARE(getValue()) expands to ((getValue()) * (getValue()))
    // getValue() is called twice!
    int result = SQUARE(getValue());
    std::cout << "SQUARE(getValue()) = " << result << std::endl;
    // Output: getValue() call #1, #2, #3, #4...
    // Watch out for side effects!

    // The correct alternative: use a function template
    // template<typename T> T square(T x) { return x * x; }
    // square(getValue()) — getValue() is called only once
    return 0;
}
```

**Pitfall 2: When a macro name is used as an identifier**

```cpp
#include <iostream>

#define foo bar

// The macro definition itself is not affected by its own recursive expansion
#define bar baz
// foo → bar → baz
// bar → baz

int main() {
    int foo = 10;  // After preprocessing: int baz = 10;
    int bar = 20;  // After preprocessing: int baz = 20; ← conflict!
    // Compile error: baz is defined twice

    return 0;
}
```

**Pitfall 3: A macro with the same name as a namespace (never do this)**

```cpp
#define MyLib  // Defines an empty macro

namespace MyLib {  // The preprocessor replaces MyLib with nothing → namespace { }
    // This namespace has become an anonymous namespace!
    // ...the behavior of all the code has changed...
}

// Lesson: don't give macros the same names as namespaces, classes, or functions
```

**Advanced technique 1: the X-Macro technique**

X-Macro is a powerful technique that uses the preprocessor to generate repetitive code:

```cpp
#include <iostream>
#include <string>

// Step 1: define the type list (the X-macro table)
#define COLOR_TABLE \
    X(RED,    0xFF0000, "Red") \
    X(GREEN,  0x00FF00, "Green") \
    X(BLUE,   0x0000FF, "Blue") \
    X(YELLOW, 0xFFFF00, "Yellow") \
    X(CYAN,   0x00FFFF, "Cyan") \
    X(MAGENTA,0xFF00FF, "Magenta") \
    X(BLACK,  0x000000, "Black") \
    X(WHITE,  0xFFFFFF, "White")

// Step 2: use the X macro to generate different forms of code

// Generate the enum
enum class Color {
    #define X(name, hex, desc) name,
    COLOR_TABLE
    #undef X
    COUNT  // Total number of enumerators
};

// Generate the mapping from enum to name
const char* colorName(Color c) {
    switch (c) {
        #define X(name, hex, desc) case Color::name: return #name;
        COLOR_TABLE
        #undef X
        default: return "UNKNOWN";
    }
}

// Generate the mapping from enum to hex value
int colorHex(Color c) {
    switch (c) {
        #define X(name, hex, desc) case Color::name: return hex;
        COLOR_TABLE
        #undef X
        default: return 0;
    }
}

// Generate the mapping from enum to description
const char* colorDesc(Color c) {
    switch (c) {
        #define X(name, hex, desc) case Color::name: return desc;
        COLOR_TABLE
        #undef X
        default: return "Unknown color";
    }
}

// Step 3: the generated code stays in sync automatically — after changing COLOR_TABLE, all mappings update automatically
int main() {
    for (int i = 0; i < static_cast<int>(Color::COUNT); ++i) {
        Color c = static_cast<Color>(i);
        std::cout << colorName(c) << " | #"
                  << std::hex << colorHex(c) << std::dec
                  << " | " << colorDesc(c) << std::endl;
    }
    std::cout << "Total colors: " << static_cast<int>(Color::COUNT) << std::endl;
    return 0;
}
```

The advantage of X-Macros: maintainers only need to modify one place, COLOR_TABLE, and all the enum values, name mappings,
and attribute mappings automatically stay consistent. This is very efficient when you need to maintain large collections of related data.

**Advanced technique 2: macros for Compile-Time Reflection**

Although C++ doesn't support true runtime reflection, macros can be used to register type information at compile time:

```cpp
#include <iostream>
#include <string>
#include <map>

#define REGISTER_CLASS(ClassName) \
    static const char* className() { return #ClassName; } \
    static int classId() { return __LINE__; } \
    static void* createInstance() { return new ClassName(); }

#define REGISTER_CLASS_WITH_BASE(ClassName, BaseClass) \
    static const char* className() { return #ClassName; } \
    static int classId() { return __LINE__; } \
    static BaseClass* createInstance() { return new ClassName(); }

class Base {
public:
    virtual ~Base() {}
    virtual void whoAmI() = 0;
};

class Dog : public Base {
    REGISTER_CLASS_WITH_BASE(Dog, Base)
public:
    void whoAmI() override {
        std::cout << "I am a " << className() << " (ID:"
                  << classId() << ")" << std::endl;
    }
};

class Cat : public Base {
    REGISTER_CLASS_WITH_BASE(Cat, Base)
public:
    void whoAmI() override {
        std::cout << "I am a " << className() << " (ID:"
                  << classId() << ")" << std::endl;
    }
};

int main() {
    Dog dog;
    Cat cat;

    dog.whoAmI();
    cat.whoAmI();

    Dog* dogPtr = static_cast<Dog*>(Dog::createInstance());
    Cat* catPtr = static_cast<Cat*>(Cat::createInstance());
    dogPtr->whoAmI();
    catPtr->whoAmI();

    delete dogPtr;
    delete catPtr;

    return 0;
}
```

5.2 A Complete Guide to Cross-Platform Conditional Compilation
--------------------------------------------------------------

In real projects, conditional compilation is mainly used to handle code differences across platforms, compilers,
and standard versions. Here is a complete cross-platform detection framework:

```cpp
#include <iostream>

// ============================================================
// Platform detection
// ============================================================
#if defined(_WIN32) || defined(_WIN64)
    #define PLATFORM_WINDOWS 1
    #if defined(_WIN64)
        #define PLATFORM_WINDOWS_64 1
    #else
        #define PLATFORM_WINDOWS_32 1
    #endif
#elif defined(__APPLE__) && defined(__MACH__)
    #define PLATFORM_APPLE 1
    #include <TargetConditionals.h>
    #if TARGET_IPHONE_SIMULATOR || TARGET_OS_IPHONE
        #define PLATFORM_IOS 1
    #else
        #define PLATFORM_MACOS 1
    #endif
#elif defined(__ANDROID__)
    #define PLATFORM_ANDROID 1
#elif defined(__linux__)
    #define PLATFORM_LINUX 1
#elif defined(__FreeBSD__)
    #define PLATFORM_FREEBSD 1
#else
    #define PLATFORM_UNKNOWN 1
#endif

// ============================================================
// Compiler detection
// ============================================================
#if defined(__clang__)
    #define COMPILER_CLANG 1
    #define COMPILER_NAME "Clang"
    #define COMPILER_VERSION (__clang_major__ * 10000 + __clang_minor__ * 100)
#elif defined(__GNUC__) || defined(__GNUG__)
    #define COMPILER_GCC 1
    #define COMPILER_NAME "GCC"
    #define COMPILER_VERSION (__GNUC__ * 10000 + __GNUC_MINOR__ * 100 + __GNUC_PATCHLEVEL__)
#elif defined(_MSC_VER)
    #define COMPILER_MSVC 1
    #define COMPILER_NAME "MSVC"
    #define COMPILER_VERSION _MSC_VER
#else
    #define COMPILER_UNKNOWN 1
    #define COMPILER_NAME "Unknown"
    #define COMPILER_VERSION 0
#endif

// ============================================================
// Architecture detection
// ============================================================
#if defined(__x86_64__) || defined(_M_X64)
    #define ARCH_X86_64 1
    #define ARCH_NAME "x86_64"
#elif defined(__i386__) || defined(_M_IX86)
    #define ARCH_X86_32 1
    #define ARCH_NAME "x86"
#elif defined(__aarch64__) || defined(_M_ARM64)
    #define ARCH_ARM_64 1
    #define ARCH_NAME "ARM64"
#elif defined(__arm__) || defined(_M_ARM)
    #define ARCH_ARM_32 1
    #define ARCH_NAME "ARM32"
#elif defined(__riscv)
    #if __riscv_xlen == 64
        #define ARCH_RISCV64 1
        #define ARCH_NAME "RISC-V 64"
    #else
        #define ARCH_RISCV32 1
        #define ARCH_NAME "RISC-V 32"
    #endif
#else
    #define ARCH_UNKNOWN 1
    #define ARCH_NAME "Unknown"
#endif

// ============================================================
// Byte order detection
// ============================================================
#if defined(__BYTE_ORDER__) && __BYTE_ORDER__ == __ORDER_BIG_ENDIAN__
    #define BIG_ENDIAN 1
#elif defined(__BYTE_ORDER__) && __BYTE_ORDER__ == __ORDER_LITTLE_ENDIAN__
    #define LITTLE_ENDIAN 1
#elif defined(_WIN32) || defined(__LITTLE_ENDIAN__)
    #define LITTLE_ENDIAN 1
#else
    #define BIG_ENDIAN 1
#endif

// ============================================================
// Choose features based on the platform
// ============================================================
#if defined(PLATFORM_WINDOWS)
    #define DLL_EXPORT __declspec(dllexport)
    #define DLL_IMPORT __declspec(dllimport)
    #define ALIGNAS(n) __declspec(align(n))
    #define THREAD_LOCAL __declspec(thread)
    #define FORCE_INLINE __forceinline
    #define NO_INLINE __declspec(noinline)
#else
    #define DLL_EXPORT __attribute__((visibility("default")))
```

5.3 The Preprocessor and Compiler Optimization
----------------------------------------------

**Dead Code Elimination**

Conditional compilation can remove unneeded code before compilation even begins, which is more efficient than runtime condition checks:

```cpp
#include <iostream>
#include <chrono>

// Comparing compile-time vs. runtime condition checks

// Method 1: preprocessor conditional compilation (zero runtime overhead)
#ifdef USE_FAST_ALGORITHM
    #define computeValue(x) ((x) * (x) + (x) + 1)  // Fast algorithm
#else
    #define computeValue(x) ((x) * (x) * (x) - (x) + 7)  // Precise algorithm
#endif

// Method 2: runtime condition check (has overhead)
int computeValueRuntime(int x, bool useFast) {
    if (useFast) {
        return x * x + x + 1;
    } else {
        return x * x * x - x + 7;
    }
}

int main() {
    const int ITERATIONS = 10000000;
    volatile int result = 0;  // Prevent the compiler from optimizing the loop away

    // Compile-time selection (method 1)
    auto start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < ITERATIONS; ++i) {
        result += computeValue(i);
    }
    auto end = std::chrono::high_resolution_clock::now();
    std::cout << "Compile-time macro: "
              << std::chrono::duration_cast<std::chrono::microseconds>(end - start).count()
              << " us" << std::endl;

    // Runtime selection (method 2)
    start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < ITERATIONS; ++i) {
        result += computeValueRuntime(i, true);
    }
    end = std::chrono::high_resolution_clock::now();
    std::cout << "Runtime if: "
              << std::chrono::duration_cast<std::chrono::microseconds>(end - start).count()
              << " us" << std::endl;

    // The preprocessor macro directly generates a fixed code path with no branching
    // The runtime if has to compare and jump on every iteration

    return 0;
}
```

**Assert — a classic application of conditional compilation**

```cpp
#include <iostream>
#include <cassert>

// Custom assertion (more flexible than the standard assert)
#ifdef DEBUG
    #define MY_ASSERT(condition, message) \
        do { \
            if (!(condition)) { \
                std::cerr << "[ASSERT FAILED] " \
                          << __FILE__ << ":" << __LINE__ << " | " \
                          << "Condition: " #condition << " | " \
                          << "Message: " << message << std::endl; \
                std::abort(); \
            } \
        } while(0)

    #define MY_VERIFY(condition) MY_ASSERT(condition, "Verification failed")
#else
    // Removed entirely in release mode
    #define MY_ASSERT(condition, message) ((void)0)
    #define MY_VERIFY(condition) ((void)0)
#endif

// Note: the standard assert is also removed when NDEBUG is defined

double divide(double a, double b) {
    MY_ASSERT(b != 0.0, "Divisor must not be zero");
    return a / b;
}

int main() {
    double result = divide(10.0, 2.0);
    std::cout << "10 / 2 = " << result << std::endl;

    // divide(10.0, 0.0);  // This would trigger the assertion

    return 0;
}
```

5.4 A Complete Guide to #pragma Directives
------------------------------------------

Although most #pragmas are compiler-specific, knowing the commonly used pragmas is essential in real-world development.

```cpp
// ============================================================
// Common GCC / Clang #pragmas
// ============================================================

// 1. Diagnostic control
#pragma GCC diagnostic push              // Save the current diagnostic state
#pragma GCC diagnostic ignored "-Wunused-variable"  // Ignore a specific warning
int unused_var = 42;

// Clang can use the same syntax too
#pragma clang diagnostic push
#pragma clang diagnostic ignored "-Wdeprecated-declarations"

#pragma clang diagnostic pop

    #pragma GCC optimize("O0")  // Turn off optimization for specific functions
    void debugFunction() {

    }

#endif

// ============================================================
// Common MSVC #pragmas
// ============================================================

#ifdef _MSC_VER
    // Warning control
    #pragma warning(push)
    #pragma warning(disable: 4996)  // Ignore the "unsafe function" warning
    strcpy(dest, src);
    #pragma warning(pop)

    // Link a library
    #pragma comment(lib, "ws2_32.lib")

    // Struct alignment
    #pragma pack(push, 1)
    struct PackedStruct {
        char c;

        short s;
    };
    #pragma pack(pop)
#endif

// ============================================================
// Standard #pragmas (defined by the C++ standard)
// ============================================================

#pragma once

// #pragma STDC FENV_ACCESS ON
```

5.5 Limitations of the Preprocessor and Modern Alternatives
-----------------------------------------------------------

Powerful as it is, the preprocessor has obvious limitations. Here is a guide to replacing macros with modern C++ features:

```cpp
// ❌ Old way: macro constants
#define PI 3.14159
#define BUFFER_SIZE 256
#define MAX(a, b) ((a) > (b) ? (a) : (b))

// ✅ New way: constexpr / const
constexpr double PI = 3.141592653589793;
constexpr int BUFFER_SIZE = 256;
template<typename T>
constexpr const T& max(const T& a, const T& b) { return a > b ? a : b; }

// ❌ Old way: conditional compilation to select features
#ifdef USE_FEATURE_X
    void process() { /* implementation A */ }
#else
    void process() { /* implementation B */ }
#endif

// ✅ New way: if constexpr + template specialization
template<bool EnableFeature>
struct Processor {
    void process() { /* implementation B */ }
};
template<>
struct Processor<true> {
    void process() { /* implementation A */ }
};
// Usage: Processor<USE_FEATURE_X>().process();

// ❌ Old way: generating code with macros
#define PROPERTY(type, name) \
    type name##_; \
    type get##name() const { return name##_; } \
    void set##name(type val) { name##_ = val; }

// ✅ New way: depends on the specific need, but templates or code generation tools may be better
// For simple getters/setters, writing them by hand is recommended for clarity
// or use your IDE's code snippet feature

// ❌ Old way: handling platform differences with macros
#ifdef _WIN32
    void sleepMs(int ms) { Sleep(ms); }
#else
    void sleepMs(int ms) { usleep(ms * 1000); }
#endif

// ✅ New way: C++17 if constexpr
// But platform differences usually still require preprocessing (pre-compilation condition checks);
// this is one of the few scenarios where preprocessor macros remain irreplaceable
```

**Scenarios where preprocessor macros are still irreplaceable:**
1. Header guards (#ifndef + #define + #endif or #pragma once)
2. Including files (#include)
3. Conditionally compiling platform-specific code (#ifdef _WIN32)
4. Predefined macros such as __FILE__ and __LINE__
5. Assertion macros (#ifdef NDEBUG)

5.6 Debugging Techniques for the Preprocessor
---------------------------------------------

Because the preprocessor runs before compilation, debugging macro expansion problems can sometimes be tricky. The following techniques can help track them down:

```bash
# Technique 1: use g++ -E to only preprocess and view the expanded code
$ g++ -E source.cpp -o source_preprocessed.cpp
$ cat source_preprocessed.cpp  # View the complete translation unit after macro expansion

# Technique 2: use -C to keep comments
$ g++ -E -C source.cpp

# Technique 3: use -dM to list all predefined macros
$ g++ -dM -E -x c++ /dev/null | sort
$ g++ -dM -E -x c++ /dev/null | grep -i version

# Technique 4: use -H to view the header include tree
$ g++ -H source.cpp
# The output shows:
# . /usr/include/stdio.h
# .. /usr/include/features.h
# ... /usr/include/stdc-predef.h
# Each dot represents one level of nesting depth

# Technique 5: use #error to deliberately trigger a compile error to check a macro's value
// In the source code:
#define MY_MACRO 42
#if MY_MACRO != 42
    #error "MY_MACRO is not 42"
#endif

// View the value of a macro after expansion
#pragma message("MY_MACRO = " STRINGIFY(MY_MACRO))

// Technique 6: use #pragma message to print macro values at compile time
#define STRINGIFY_HELPER(x) #x
#define STRINGIFY(x) STRINGIFY_HELPER(x)
#pragma message("Current line: " STRINGIFY(__LINE__))
#pragma message("Compilation date: " __DATE__)
#pragma message("C++ standard: " STRINGIFY(__cplusplus))
```

5.7 Managing Header Dependencies
--------------------------------

In large projects, careless #includes slow down compilation. Here are the best practices:

```cpp
// ============================================================
// Principles of header inclusion
// ============================================================

// 1. Include only the headers you need (don't include unnecessary ones)
// ❌ Bad habit: including a header for an entire library
// #include <bits/stdc++.h>  // Strongly discouraged! Non-standard and slows compilation

// ✅ Good habit: include precisely
#include <iostream>   // If you only need cout
#include <string>     // If you only need string
#include <vector>     // If you only need vector

// 2. Prefer forward declarations to reduce header dependencies
// header.h
#pragma once

// Forward declarations (declare only the class name without the full definition, avoiding transitive header dependencies)
namespace MyLib {
    class DataBase;         // Forward declaration
    class Logger;           // Forward declaration
    struct ConnectionInfo; // Forward declaration
}

namespace App {
    class Manager {
    public:
        void setDatabase(MyLib::DataBase* db);  // Pointers/references don't need the full definition
        void log(MyLib::Logger* logger);

    private:
        MyLib::DataBase* database_;  // A pointer; doesn't need the full definition
        // MyLib::ConnectionInfo info_; // Error! Needs the full definition
    };
}

// 3. The self-sufficient header principle
// Every header should compile on its own (not depend on the include order of other headers)
// After writing a header, verify it by including it first in its .cpp file
// myheader.cpp
#include "myheader.h"  // First line
// #include <other_headers...>  // Later includes

// 4. Use a compilation firewall (Pimpl Idiom / Cheshire Cat)
// widget.h
#pragma once
#include <memory>

class Widget {
public:
    Widget();
    ~Widget();  // Must be implemented in the .cpp (to destroy the unique_ptr)
    void doSomething();
private:
    struct Impl;                    // Forward-declare the implementation class
    std::unique_ptr<Impl> pImpl_;  // Hide implementation details
};

// widget.cpp
#include "widget.h"
#include <string>      // Included only in the .cpp
#include <vector>      // These dependencies are not propagated to files that include widget.h

struct Widget::Impl {
    std::string name;
    std::vector<int> data;
    int counter;
    // ... complex internal state
};

Widget::Widget() : pImpl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;
void Widget::doSomething() { /* use pImpl_->name, etc. */ }
```

================================================================================
### Chapter Summary
================================================================================

Key points of this chapter:

1. **The preprocessor is the first stage of compilation**: a pure text substitution engine. It runs before the compiler parses C++ syntax
   and knows nothing about types, scope, or C++ language constructs.

2. **The four stages of compilation**: preprocessing → compilation → assembly → linking. The preprocessor outputs a translation unit,
   the compiler processes the AST and generates assembly, the assembler produces object files, and the linker merges them into an executable.

3. **#include** is just a simple copy-paste of file contents. Header guards (#ifndef + #define +
   #endif or #pragma once) prevent multiple inclusion.

4. **#define** defines macros: untyped, unscoped text substitution. Always wrap macro parameters
   and macro bodies in parentheses to avoid operator precedence problems. Prefer constexpr and inline functions over macros.

5. **Conditional compilation** (#ifdef, #ifndef, #if, #else, #elif, #endif) lets you selectively compile code depending on
   which macros are defined; it is the core mechanism for cross-platform support and DEBUG/RELEASE mode switching.

6. The **# operator** turns a macro argument into a string literal, and the **## operator** joins two tokens. They are
   the foundation of advanced macro techniques such as code generation and automatic naming.

7. **Predefined macros** (__FILE__, __LINE__, __DATE__, __TIME__, __cplusplus) provide
   compile-time context information and are indispensable in debug logging.

8. **Never write using namespace in a header file**, and **never use a namespace name
   as a macro name**.

9. Although modern C++ offers many alternatives to macros (constexpr, inline functions, templates,
   if constexpr), the role of preprocessing in header management, platform detection, compile-time configuration, and so on
   remains irreplaceable.

6.1 The Do-While-Zero Idiom in Depth

```cpp
// Classic mistake: a multi-statement macro without a wrapper
#define BAD_SWAP(a, b) auto tmp = a; a = b; b = tmp

// If used after an if:
// if (condition)
//     BAD_SWAP(x, y);
// else
//     doOtherThing();
// After expansion:
// if (condition)
//     auto tmp = x;    ← the if body ends here!
// x = y;               ← this always executes!
// y = tmp;             ← this always executes too!
// ;                    ← empty statement
// else                 ← syntax error! no matching if
//     doOtherThing();

// The right way:
#define GOOD_SWAP(a, b) do { auto tmp = (a); (a) = (b); (b) = tmp; } while(0)
// do { ... } while(0) requires a trailing semicolon, perfectly absorbing the semicolon the user writes
```

6.2 The Line-Continuation Pitfall in Multi-Line Macros

```cpp
// The continuation character \ must be the last character on the line (no spaces or comments after it)
#define MULTI_LINE_MACRO \
    int a = 1; \      // ← these comments are OK (GCC)
    int b = 2;        // ← the last line doesn't need \

// Error: invisible characters (spaces/tabs) after the \
#define BROKEN_MACRO \
    int x = 1; \___   // ← the underscores indicate a space here
    int y = 2;        //   this makes the preprocessor think the macro body has already ended
```

6.6 The Role of the Preprocessor in Unit Testing

```cpp
// Test frameworks such as catch.hpp / doctest make heavy use of the preprocessor
// Below is a simplified test framework

#define TEST_CASE(name) \
    static void test_function_##name(); \
    static bool test_registered_##name = \
        TestRegistry::registerTest(#name, test_function_##name); \
    static void test_function_##name()

#define CHECK(condition) \
    do { \
        if (!(condition)) { \
            std::cerr << "FAIL: " << __FILE__ << ":" << __LINE__ \
                      << " | CHECK(" << #condition << ") failed!" \
                      << std::endl; \
            throw std::runtime_error("Test failed"); \
        } \
    } while(0)

#define CHECK_EQ(a, b) \
    do { \
        auto _a = (a); auto _b = (b); \
        if (!(_a == _b)) { \
            std::cerr << "FAIL: " << __FILE__ << ":" << __LINE__ \
                      << " | CHECK_EQ(" << #a << ", " << #b \
                      << ") failed! (" << _a << " != " << _b << ")" \
                      << std::endl; \
            throw std::runtime_error("Test failed"); \
        } \
    } while(0)

// Test framework core
namespace TestRegistry {
    using TestFunc = void(*)();
    std::map<const char*, TestFunc> tests;

    void registerTest(const char* name, TestFunc func) {
        tests[name] = func;
    }

    int runAll() {
        int passed = 0, failed = 0;
        for (auto& [name, func] : tests) {
            std::cout << "Running test: " << name << " ... ";
            try {
                func();
                std::cout << "PASSED" << std::endl;
                ++passed;
            } catch (const std::exception& e) {
                std::cout << "FAILED (" << e.what() << ")" << std::endl;
                ++failed;
            }
        }
        std::cout << "\nTotal: " << passed << " passed, "
                  << failed << " failed" << std::endl;
        return failed;
    }
}

// Example test cases
TEST_CASE(SimpleMath) {
    CHECK(1 + 1 == 2);
    CHECK_EQ(3 * 4, 12);
}

TEST_CASE(StringOperations) {
    std::string s = "hello";
    CHECK_EQ(s.size(), 5u);
}

// In real projects, test case registration is automatic; no explicit calls are needed
// All TEST_CASE functions are registered in TestRegistry before the program starts
```

6.7 Final Summary of Preprocessor Practices

When you use the preprocessor, remember this mnemonic:

```
Parenthesize every macro,      // Wrap macro parameters and the whole body in parentheses
Keep do-while-zero in mind,    // Use do { } while(0) for multi-statement macros
Don't skip namespaces,         // Prefer namespaces for code that can be organized with them
Macro names go in UPPERCASE,   // All-caps macro names are recognizable at a glance
Header guards are the minimum, // Every header file must have one
Prefer the C++ way.            // Don't use a macro if you can avoid it
```

```cpp
// Collection of counterexamples (don't write code like this)
#define MIN(a,b) a<b?a:b                    // No parentheses
#define INIT int a=1;int b=2;              // Multiple statements without do-while(0)
#define my_value 100                       // Macro name not uppercase (can't tell macros from variables)
#define value 42                           // Short, generic macro names pollute the global scope
// Header file without any guard              // Multiple inclusion causes compile errors
#define max(a,b) ((a)>(b)?(a):(b))        // There's already std::max!
```

These summaries will help you keep good habits for using the preprocessor correctly as you study the following chapters.

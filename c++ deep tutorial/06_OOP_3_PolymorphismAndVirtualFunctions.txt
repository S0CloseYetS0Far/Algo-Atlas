I. Virtual Functions and Dynamic Binding: A Basic Example
------------------------------------

Polymorphism is one of the most important features of object-oriented programming.
Through virtual functions, a base class pointer/reference can call the correct function version at runtime based on the actual object type.

[Example 1-1] Without virtual functions (static binding) vs with virtual functions (dynamic binding):

```cpp
#include <iostream>
#include <string>

// ====== Version without virtual functions (static binding) ======
class Animal_NoVirtual {
public:
    void makeSound() {
        std::cout << "Animal_NoVirtual makes some sound" << std::endl;
    }
};

class Dog_NoVirtual : public Animal_NoVirtual {
public:
    void makeSound() {
        std::cout << "Dog_NoVirtual barks: Woof!" << std::endl;
    }
};

// ====== Version with virtual functions (dynamic binding) ======
class Animal {
public:
    virtual void makeSound() {
        std::cout << "Animal makes some sound" << std::endl;
    }
    virtual ~Animal() {}  // virtual destructor!
};

class Dog : public Animal {
public:
    void makeSound() override {   // the override keyword ensures a correct override
        std::cout << "Dog barks: Woof! Woof!" << std::endl;
    }
};

class Cat : public Animal {
public:
    void makeSound() override {
        std::cout << "Cat meows: Meow~" << std::endl;
    }
};

int main() {
    std::cout << "===== Static binding demo =====" << std::endl;
    Dog_NoVirtual dnv;
    Animal_NoVirtual* ptr_nv = &dnv;
    ptr_nv->makeSound();  // calls Animal_NoVirtual::makeSound()
                          // -- even though the actual object is a Dog, the base version was chosen at compile time!

    std::cout << "\n===== Dynamic binding demo =====" << std::endl;
    Dog dog;
    Cat cat;

    Animal* animals[] = { &dog, &cat };

    for (auto* a : animals) {
        a->makeSound();  // calls the version for the actual object type!
        // Dog calls Dog::makeSound(), Cat calls Cat::makeSound()
    }

    std::cout << "\n===== Why virtual destructors matter =====" << std::endl;
    Animal* ptr = new Dog();
    delete ptr;  // if ~Animal() were not virtual, only Animal's destructor would be called
                 // Dog's destructor would not be called! Memory leak!
                 // Because ~Animal() is virtual, Dog::~Dog() -> Animal::~Animal() is called correctly
    return 0;
}
```

II. Low-Level Computer Principles: The Virtual Function Table (vtable) Explained
------------------------------------

Virtual functions are the core mechanism C++ uses to implement runtime polymorphism. The compiler uses a "virtual function table" (vtable)
and a "virtual table pointer" (vptr) to implement dynamic binding (also called late binding/runtime binding).

[Principle 2-1] The structure of the virtual function table

Every class that contains virtual functions (or derives from a virtual base class) has a virtual function table (vtable).
The vtable is an array of function pointers that stores the addresses of all the class's virtual functions.

```cpp
class Base {
public:
    int baseData;
    virtual void func1() { std::cout << "Base::func1" << std::endl; }
    virtual void func2() { std::cout << "Base::func2" << std::endl; }
    void nonVirtual()   { std::cout << "Base::nonVirtual" << std::endl; }
};

class Derived : public Base {
public:
    int derivedData;
    void func1() override { std::cout << "Derived::func1" << std::endl; }
    virtual void func3()  { std::cout << "Derived::func3" << std::endl; }
};
```

Memory layout of a Base object:

  Address  Content
  ────────────────────────────────────
  &obj   ┌ vptr ──────→ Base vtable
         │             ┌─────────────────────┐
         │             │ &Base::func1         │ <- slot 0
         │             │ &Base::func2         │ <- slot 1
         │             │ &type_info(Base)     │ <- RTTI info
         │             └─────────────────────┘
  +8     │ baseData
         └────────────────────────

Memory layout of a Derived object:

  Address  Content
  ────────────────────────────────────
  &obj   ┌ vptr ──────→ Derived vtable
         │             ┌─────────────────────┐
         │             │ &Derived::func1      │ <- slot 0 (overridden)
         │             │ &Base::func2         │ <- slot 1 (not overridden)
         │             │ &Derived::func3      │ <- slot 2 (new virtual function)
         │             │ &type_info(Derived)  │ <- RTTI info
         │             └─────────────────────┘
  +8     │ baseData         <- base class subobject
  +12    │ [padding 4B]
  +16    │ derivedData      <- added by the derived class
         └────────────────────────

Key points:
  1. The vptr is located at the very beginning of the object's memory (offset 0)
  2. The vptr is initialized when the constructor runs (pointing to the current class's vtable)
  3. Non-virtual functions are not in the vtable; calls to them are statically bound at compile time
  4. The vtable is stored in the read-only data segment (.rodata)
  5. All objects of the same class share the same vtable

[Principle 2-2] Virtual function calls at the assembly level

Consider the following call:

```cpp
Base* ptr = new Derived();
ptr->func1();  // virtual function call
```

The code generated by the compiler is equivalent to (pseudocode):

```cpp
// Step 1: find the vtable through the vptr
vtable_ptr* vt = *(vtable_ptr**)ptr;  // read the first 8 bytes of the object (vptr)
// Step 2: fetch the function pointer from the vtable
void (*func_ptr)() = vt[0];           // slot 0 = func1
// Step 3: call the function
func_ptr(ptr);                         // this = ptr
```

The corresponding x86-64 assembly pseudocode:

```asm
; assembly pseudocode for ptr->func1()
mov  rax, [rdi]        ; rax = vptr (rdi = this pointer)
                        ; dereference the this pointer, reading the first 8 bytes to get the vtable address
mov  rax, [rax]        ; rax = vtable[0] (address of the first virtual function)
                        ; dereference the vtable pointer, reading the first entry
call rax                ; call the function
```

Compare with the assembly pseudocode for a non-virtual function (direct call, a single jump):

```asm
; assembly pseudocode for ptr->nonVirtual() (static binding)
call Base::nonVirtual  ; directly call a known address, a single call instruction
```

The overhead of a virtual function call:
  - One extra pointer dereference (this -> vptr -> vtable -> function)
  - Cannot be inlined (the compiler doesn't know which version will be called at runtime)
  - The vtable itself takes memory (one per class, plus an extra 8-byte vptr per object)

But compared with the flexibility of virtual functions, this overhead is usually negligible on modern hardware.
Unless you are in a tight loop on the hottest path, you don't need to worry about the performance impact of virtual functions.

[Principle 2-3] RTTI and type_info

The vtable also stores RTTI (Run-Time Type Information), including the type_info object,
which is what makes dynamic_cast and typeid possible.

```cpp
#include <typeinfo>
#include <iostream>

class Base {
    virtual void dummy() {}
public:
    virtual ~Base() {}
};

class Derived : public Base {};

int main() {
    Base* b1 = new Base();
    Base* b2 = new Derived();

    std::cout << "b1 type: " << typeid(*b1).name() << std::endl;
    std::cout << "b2 type: " << typeid(*b2).name() << std::endl;
    // typeid(*ptr).name() returns the type name (varies by compiler)

    // dynamic_cast: safe downcasting
    if (Derived* d = dynamic_cast<Derived*>(b2)) {
        std::cout << "b2 successfully cast to Derived*" << std::endl;
    } else {
        std::cout << "b2 is NOT a Derived" << std::endl;
    }

    if (Derived* d = dynamic_cast<Derived*>(b1)) {
        std::cout << "b1 successfully cast to Derived*" << std::endl;
    } else {
        std::cout << "b1 is NOT a Derived (returns nullptr)" << std::endl;
    }

    delete b1;
    delete b2;
    return 0;
}
```

[Principle 2-4] Virtual function behavior in constructors and destructors

When a virtual function is called in a constructor or destructor, the current class's version is used,
not the derived class's version. This is called "static binding in constructors".

```cpp
#include <iostream>

class Base {
public:
    Base() {
        std::cout << "Base constructor:" << std::endl;
        virtualFunc();  // at this point Base::virtualFunc is called, not Derived's!
    }
    virtual void virtualFunc() {
        std::cout << "  Base::virtualFunc()" << std::endl;
    }
    virtual ~Base() {
        std::cout << "Base destructor:" << std::endl;
        virtualFunc();  // calls Base::virtualFunc
    }
};

class Derived : public Base {
public:
    Derived() {
        std::cout << "Derived constructor:" << std::endl;
        virtualFunc();  // at this point Derived::virtualFunc is called
    }
    void virtualFunc() override {
        std::cout << "  Derived::virtualFunc()" << std::endl;
    }
    ~Derived() {
        std::cout << "Derived destructor:" << std::endl;
        virtualFunc();  // calls Derived::virtualFunc
    }
};

int main() {
    Derived d;
    return 0;
}
/* Output:
Base constructor:
  Base::virtualFunc()         <- during base construction, vptr points to Base's vtable
Derived constructor:
  Derived::virtualFunc()      <- during derived construction, vptr already points to Derived's vtable
Derived destructor:
  Derived::virtualFunc()      <- during derived destruction, vptr is still on Derived's vtable
Base destructor:
  Base::virtualFunc()         <- during base destruction, vptr has reverted to Base's vtable
*/
```

Reason: the vptr is updated step by step during construction.
  - On entering Base's constructor, the vptr points to Base's vtable
  - After Base's construction completes and Derived's constructor is entered, the vptr points to Derived's vtable
  - Destruction proceeds in reverse

[Principle 2-5] How virtual functions affect object size

```cpp
#include <iostream>

class A {
    int x;
public:
    void nonVirtualFunc() {}
};

class B {
    int x;
public:
    virtual void virtualFunc() {}  // introducing a virtual function -> adds a vptr
};

class C {
public:
    virtual void vfunc1() {}
    virtual void vfunc2() {}
    // no matter how many virtual functions, there is only one vptr
};

int main() {
    std::cout << "sizeof(A) = " << sizeof(A) << std::endl;  // 4 (just the int)
    std::cout << "sizeof(B) = " << sizeof(B) << std::endl;  // 16 (vptr=8B + int=4B + padding=4B)
    std::cout << "sizeof(C) = " << sizeof(C) << std::endl;  // 8 (just the vptr)
    return 0;
}

// Memory layout comparison:
// A: [x(4B)]
// B: [vptr(8B)][x(4B)][padding(4B)]
// C: [vptr(8B)]
// The vptr is always at the start of the object!
```

2.1 The virtual Keyword
------------------------------------

```cpp
// virtual is used to declare virtual functions
class Base {
public:
    virtual void func1() { }         // ordinary virtual function
    virtual void func2() = 0;        // pure virtual function
    virtual ~Base() { }              // virtual destructor (important!)

    // virtual cannot be used on:
    // 1. Static member functions (static)
    // 2. Non-member functions (only member functions can be virtual)
    // 3. Constructors (the vptr isn't set up yet during construction)
    // 4. Template functions (template instantiation happens at compile time)
};

// The virtual keyword can be omitted in the derived class (but override is recommended instead)
class Derived : public Base {
public:
    // The following three forms are equivalent (func1 automatically becomes virtual):
    void func1() { }                   // automatically virtual (inherited)
    virtual void func1() { }           // explicit virtual (not recommended, use override)
    void func1() override { }          // recommended! compile-time check that it is a correct override

    void func2() override { }          // the pure virtual function must be implemented
};
```

2.2 The override Keyword (C++11)
------------------------------------

```cpp
class Base {
public:
    virtual void draw(int x, int y) { }
    virtual void resize(double factor) { }
    virtual std::string getName() const { return "Base"; }
};

class Derived : public Base {
public:
    // override ensures the function signature matches exactly
    void draw(int x, int y) override { }   // OK, matches Base::draw

    // None of the following are correct -- override reports an error!
    // void draw(int x) override { }       // Error: different parameter list
    // void draw(float x, float y) override { } // Error: different parameter types
    // void resize(int factor) override { }    // Error: int vs double
    // std::string getName() override { }      // Error: missing const qualifier!

    // If the base class function is modified (e.g. a parameter is added), override catches the error right away
    // This is the biggest benefit of using override
};
```

Benefits of override:
  1. Guarantees at compile time that you really are overriding a base class virtual function
  2. If the base class changes the function signature, the derived class gets a compile error (instead of failing silently)
  3. Improves readability -- clearly marks the function as an override

2.3 Pure Virtual Functions (= 0) and Abstract Classes
------------------------------------

```cpp
// Abstract class -- contains at least one pure virtual function and cannot be instantiated
class Shape {
public:
    virtual double area() const = 0;        // pure virtual function
    virtual double perimeter() const = 0;   // pure virtual function
    virtual void draw() const = 0;          // pure virtual function

    // An abstract class can have non-virtual member functions
    void setColor(const std::string& c) { color = c; }

    // An abstract class can have constructors (called by derived classes)
    Shape(const std::string& c) : color(c) {}

    virtual ~Shape() = default;  // virtual destructor
protected:
    std::string color;
};

// Concrete class -- must implement all pure virtual functions
class Circle : public Shape {
    double radius;
public:
    Circle(double r, const std::string& c) : Shape(c), radius(r) {}

    double area() const override {
        return 3.14159 * radius * radius;
    }
    double perimeter() const override {
        return 2 * 3.14159 * radius;
    }
    void draw() const override {
        std::cout << "Drawing Circle with radius " << radius << std::endl;
    }
};

// Shape s;  // Error! An abstract class cannot be instantiated
// Circle c(5, "red");  // OK
```

Properties of abstract classes:
  1. Objects cannot be created directly (new Shape() is an error)
  2. Can have constructors/destructors
  3. Can have non-virtual member functions and data members
  4. Polymorphic behavior of derived objects is accessed through base class pointers/references
  5. A pure virtual function can have an implementation (rare): virtual void func() = 0 {}

2.4 Virtual Destructors
------------------------------------

```cpp
#include <iostream>

// Wrong example: no virtual destructor
class BadBase {
public:
    ~BadBase() { std::cout << "~BadBase()" << std::endl; }
};

class BadDerived : public BadBase {
    int* data;
public:
    BadDerived() : data(new int[1000]) {
        std::cout << "BadDerived() allocated 1000 ints" << std::endl;
    }
    ~BadDerived() {
        delete[] data;
        std::cout << "~BadDerived() freed 1000 ints" << std::endl;
    }
};

void badExample() {
    BadBase* ptr = new BadDerived();
    delete ptr;  // only ~BadBase() is called! ~BadDerived() is not called!
                 // data leaks! The memory for 1000 ints is never freed!
}

// Correct example: with a virtual destructor
class GoodBase {
public:
    virtual ~GoodBase() { std::cout << "~GoodBase()" << std::endl; }
};

class GoodDerived : public GoodBase {
    int* data;
public:
    GoodDerived() : data(new int[1000]) {
        std::cout << "GoodDerived() allocated 1000 ints" << std::endl;
    }
    ~GoodDerived() override {
        delete[] data;
        std::cout << "~GoodDerived() freed 1000 ints" << std::endl;
    }
};

void goodExample() {
    GoodBase* ptr = new GoodDerived();
    delete ptr;  // calls ~GoodDerived() -> ~GoodBase()
                 // resources are released correctly!
}

// Rule: if a class has virtual functions, its destructor should also be virtual
// If a class is designed to be a base class, its destructor must be virtual
```

2.5 final on Virtual Functions (C++11)
------------------------------------

```cpp
class Base {
public:
    virtual void func1() = 0;
    virtual void func2() { }

    // final prevents further overriding
    virtual void finalFunc() final {
        std::cout << "This cannot be overridden" << std::endl;
    }
};

class Derived : public Base {
public:
    void func1() override { }
    void func2() override { }
    // void finalFunc() override { }  // Error! A final function cannot be overridden
};

class FurtherDerived : public Derived {
public:
    void func1() override { }  // OK, Base did not mark func1 final
    void func2() override { }  // OK, Base did not mark func2 final
    // void finalFunc() override { }  // Error! It is final
};

// final can also be used on classes (introduced in Chapter 5)
class FinalClass final {
    // ...
};
// class Derived2 : public FinalClass {};  // Error!
```

2.6 Covariant Return Types
------------------------------------

```cpp
class Base {
public:
    virtual Base* clone() const {
        std::cout << "Base::clone()" << std::endl;
        return new Base(*this);
    }
    virtual ~Base() = default;
    int baseData = 0;
};

class Derived : public Base {
public:
    // Covariant return type: returns Derived* instead of Base*
    // Condition: the return type is a pointer/reference, and Derived derives from Base
    Derived* clone() const override {
        std::cout << "Derived::clone()" << std::endl;
        return new Derived(*this);
    }
    int derivedData = 42;
};

int main() {
    Derived d;
    d.derivedData = 100;

    // Advantage of covariant return types: no downcast needed
    Derived* cloned = d.clone();  // returns Derived*, usable directly
    std::cout << "derivedData: " << cloned->derivedData << std::endl;

    // Polymorphic call through a base class pointer
    Base* ptr = &d;
    Base* cloned2 = ptr->clone();  // returns Base*, but it is actually a Derived*
    // Derived* cloned3 = ptr->clone();  // Error! The static type is Base*, so it returns Base*
    delete cloned;
    delete cloned2;
    return 0;
}

// Use cases for covariant return types:
// the clone() factory pattern, getThis() methods, etc.
```

2.7 Behavior of Default Arguments in Virtual Functions
------------------------------------

```cpp
#include <iostream>

class Base {
public:
    // Virtual function with a default argument
    virtual void print(int x = 10) {
        std::cout << "Base::print(" << x << ")" << std::endl;
    }
};

class Derived : public Base {
public:
    // Overrides the virtual function -- but with a different default argument!
    void print(int x = 20) override {  // note: default argument is 20, not 10
        std::cout << "Derived::print(" << x << ")" << std::endl;
    }
};

int main() {
    Derived d;
    Base* ptr = &d;
    Derived* dptr = &d;

    // Default arguments are statically bound!
    d.print();       // Derived::print(20) -- calls the Derived version with Derived's default
    ptr->print();    // Derived::print(10) -- calls the Derived version but uses Base's default!
                     // Pitfall! Virtual functions are dynamically bound, but default arguments are statically bound!

    dptr->print();   // Derived::print(20) -- both static and dynamic types are Derived
    return 0;
}

// Core rule:
// Dynamic binding of virtual functions -> which function is called is decided at runtime by the actual object type
// Static binding of default arguments -> the default value is decided at compile time by the pointer's static type
//
// Best practice: never change default arguments in an overriding virtual function!
```

2.8 typeid and dynamic_cast
------------------------------------

```cpp
#include <iostream>
#include <typeinfo>
#include <vector>

class Animal {
public:
    virtual ~Animal() = default;
    virtual std::string species() const = 0;
};

class Dog : public Animal {
public:
    void bark() { std::cout << "Woof!" << std::endl; }
    std::string species() const override { return "Dog"; }
};

class Cat : public Animal {
public:
    void meow() { std::cout << "Meow!" << std::endl; }
    std::string species() const override { return "Cat"; }
};

class Bird : public Animal {
public:
    void chirp() { std::cout << "Chirp!" << std::endl; }
    std::string species() const override { return "Bird"; }
};

void processAnimal(Animal* animal) {
    std::cout << "Processing: " << animal->species() << std::endl;

    // typeid checks the type -- requires RTTI to be enabled
    if (typeid(*animal) == typeid(Dog)) {
        std::cout << "  It's exactly a Dog!" << std::endl;
    } else if (typeid(*animal) == typeid(Cat)) {
        std::cout << "  It's exactly a Cat!" << std::endl;
    }

    // dynamic_cast: safe type conversion
    // For pointers: returns nullptr on failure
    if (auto* dog = dynamic_cast<Dog*>(animal)) {
        dog->bark();  // safely call a Dog-specific method
    } else if (auto* cat = dynamic_cast<Cat*>(animal)) {
        cat->meow();  // safely call a Cat-specific method
    }

    // For references: throws std::bad_cast on failure
    try {
        Dog& dogRef = dynamic_cast<Dog&>(*animal);
        std::cout << "  Reference cast to Dog succeeded" << std::endl;
    } catch (const std::bad_cast& e) {
        std::cout << "  Not a Dog reference" << std::endl;
    }
}

int main() {
    std::vector<Animal*> animals;
    animals.push_back(new Dog());
    animals.push_back(new Cat());
    animals.push_back(new Bird());
    animals.push_back(new Dog());

    for (auto* a : animals) {
        processAnimal(a);
        std::cout << "---" << std::endl;
    }

    for (auto* a : animals) delete a;
    return 0;
}
```

Use cases for dynamic_cast:
  1. Downcasting (from a base class pointer to a derived class pointer)
  2. Cross-casting (from one base class to another in multiple inheritance)
  3. Special handling based on the actual type (though virtual functions should be used instead whenever possible)

Note: dynamic_cast requires RTTI (Run-Time Type Identification) support.
If RTTI is disabled at compile time (-fno-rtti), dynamic_cast is unavailable.

Case 1: Zoo Animal Simulation (Introduction to Polymorphism)
------------------------------------

[Real-life scenario] A zoo audio-guide system. After a visitor selects an animal, the system plays that animal's sound.
Pure virtual functions define the animal interface, and each animal overrides makeSound.

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>
#include <iomanip>

// ====== Debug macro (Chapter 2) ======
#ifdef ZOO_DEBUG
    #define ZOO_LOG(msg) std::cout << "[ZOO] " << msg << std::endl
#else
    #define ZOO_LOG(msg)
#endif

namespace zoo {

// ====== Abstract base class: Animal ======
class Animal {
protected:
    std::string name;
    int age;
    std::string habitat;   // habitat

public:
    Animal(const std::string& n, int a, const std::string& h)
        : name(n), age(a), habitat(h) {
        ZOO_LOG("Animal born: " + n);
    }

    // Virtual destructor -- crucial!
    virtual ~Animal() {
        ZOO_LOG("Animal gone: " + name);
    }

    // Pure virtual function -- every animal must have a sound
    virtual std::string makeSound() const = 0;

    // Pure virtual function -- get the diet
    virtual std::string getDiet() const = 0;

    // Ordinary virtual function -- has a default implementation
    virtual std::string getInfo() const {
        return name + " (age:" + std::to_string(age) +
               ", habitat:" + habitat + ")";
    }

    // Non-virtual functions
    const std::string& getName() const { return name; }
    int getAge() const { return age; }
    void celebrateBirthday() { age++; }

    virtual std::string getCategory() const = 0;
};

// ====== Derived class: Dog ======
class Dog : public Animal {
public:
    Dog(const std::string& n, int a)
        : Animal(n, a, "Land") {}
    ~Dog() override { ZOO_LOG("Dog destructed: " + name); }

    std::string makeSound() const override {
        return "Arf arf! Woof Woof! \xF0\x9F\x90\xB6";
    }

    std::string getDiet() const override {
        return "Omnivore: dog food, meat, vegetables";
    }

    std::string getInfo() const override {
        return Animal::getInfo() + " [Dog]";
    }

    std::string getCategory() const override { return "Mammal"; }
};

// ====== Derived class: Cat ======
class Cat : public Animal {
public:
    Cat(const std::string& n, int a)
        : Animal(n, a, "Land") {}
    ~Cat() override { ZOO_LOG("Cat destructed: " + name); }

    std::string makeSound() const override {
        return "Mew mew! Meow~ \xF0\x9F\x90\xB1";
    }

    std::string getDiet() const override {
        return "Carnivore: cat food, fish, chicken";
    }

    std::string getInfo() const override {
        return Animal::getInfo() + " [Cat]";
    }

    std::string getCategory() const override { return "Mammal"; }
};

// ====== Derived class: Bird ======
class Bird : public Animal {
private:
    double wingspan;  // wingspan (cm)

public:
    Bird(const std::string& n, int a, double w)
        : Animal(n, a, "Sky/Forest"), wingspan(w) {}
    ~Bird() override { ZOO_LOG("Bird destructed: " + name); }

    std::string makeSound() const override {
        return "Tweet tweet! Chirp Chirp! \xF0\x9F\x90\xA6";
    }

    std::string getDiet() const override {
        return "Omnivore: seeds, insects, berries";
    }

    std::string getInfo() const override {
        return Animal::getInfo() + " [Bird] wingspan:" +
               std::to_string(wingspan) + "cm";
```

Case 2: Upgraded Graphics Drawing System (Polymorphism + Covariant Return Types)
------------------------------------

[Real-life scenario] CAD software needs to draw many kinds of shapes. Building on the Shape hierarchy from Chapter 5,
polymorphic draw() and area() are added to demonstrate complete dynamic binding.

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>
#include <cmath>
#include <iomanip>

// ====== Debug macro ======
#define CAD_DEBUG 1
#if CAD_DEBUG
    #define CAD_LOG(msg) std::cout << "[CAD] " << msg << std::endl
#else
    #define CAD_LOG(msg)
#endif

namespace cad {

// ====== Abstract base class: Drawable ======
class Drawable {
public:
    virtual void draw() const = 0;
    virtual ~Drawable() = default;
};

// ====== Abstract base class: Shape ======
class Shape : public Drawable {
protected:
    double x, y;
    std::string color;
    static int shapeCount;

public:
    Shape(double xVal, double yVal, const std::string& c)
        : x(xVal), y(yVal), color(c) {
        shapeCount++;
        CAD_LOG("Shape created at (" + std::to_string(x) + "," +
                std::to_string(y) + ")");
    }

    virtual ~Shape() {
        shapeCount--;
        CAD_LOG("Shape destroyed");
    }

    virtual double area() const = 0;
    virtual double perimeter() const = 0;
    virtual std::string getType() const = 0;

    // Covariant return type -- derived classes can return a derived class pointer
    virtual Shape* clone() const {
        CAD_LOG("Shape::clone() -- should be overridden");
        return nullptr;
    }

    void move(double dx, double dy) { x += dx; y += dy; }
    double getX() const { return x; }
    double getY() const { return y; }
    const std::string& getColor() const { return color; }

    virtual void printInfo() const {
        std::cout << getType() << " {" << color << "} at (" << x
                  << "," << y << ") area=" << std::fixed
                  << std::setprecision(2) << area();
    }

    static int getShapeCount() { return shapeCount; }
};

int Shape::shapeCount = 0;

// ====== Derived class: Circle ======
class Circle : public Shape {
private:
    double radius;

public:
    Circle(double xVal, double yVal, const std::string& c, double r)
        : Shape(xVal, yVal, c), radius(r) { }

    double area() const override {
        return M_PI * radius * radius;
    }

    double perimeter() const override {
        return 2 * M_PI * radius;
    }

    void draw() const override {
        std::cout << "\xF0\x9F\x94\xB5 Drawing circle: radius " << radius
                  << " area " << area() << std::endl;
    }

    std::string getType() const override { return "Circle"; }

    // Covariant return type -- returns Circle*
    Circle* clone() const override {
        return new Circle(x, y, color, radius);
    }

    double getRadius() const { return radius; }
};

// ====== Derived class: Rectangle ======
class Rectangle : public Shape {
private:
    double width, height;

public:
    Rectangle(double xVal, double yVal, const std::string& c,
              double w, double h)
        : Shape(xVal, yVal, c), width(w), height(h) { }

    double area() const override {
        return width * height;
    }

    double perimeter() const override {
        return 2 * (width + height);
    }

    void draw() const override {
        std::cout << "\xF0\x9F\x9F\xAB Drawing rectangle: " << width << "x"
                  << height << " area " << area() << std::endl;
    }

    std::string getType() const override { return "Rectangle"; }

    Rectangle* clone() const override {
        return new Rectangle(x, y, color, width, height);
    }
};

// ====== Derived class: Triangle ======
class Triangle : public Shape {
private:
    double sideA, sideB, sideC;

public:
    Triangle(double xVal, double yVal, const std::string& c,
             double a, double b, double sideCVal)
        : Shape(xVal, yVal, c), sideA(a), sideB(b), sideC(sideCVal) { }

    // Compute the area with Heron's formula
    double area() const override {
        double s = (sideA + sideB + sideC) / 2.0;
        return std::sqrt(s * (s - sideA) * (s - sideB) * (s - sideC));
    }

    double perimeter() const override {
        return sideA + sideB + sideC;
    }

    void draw() const override {
        std::cout << "\xF0\x9F\x94\xBA Drawing triangle: sides("
                  << sideA << "," << sideB << "," << sideC
                  << ") area " << area() << std::endl;
    }

    std::string getType() const override { return "Triangle"; }

    Triangle* clone() const override {
        return new Triangle(x, y, color, sideA, sideB, sideC);
    }
};

// ====== Polymorphic operations ======
void renderScene(const std::vector<std::unique_ptr<Shape>>& scene) {
    std::cout << "\n===== Rendering Scene =====" << std::endl;
    for (const auto& shape : scene) {
        shape->draw();
    }
}

double totalArea(const std::vector<std::unique_ptr<Shape>>& scene) {
    double total = 0.0;
    for (const auto& shape : scene) {
        total += shape->area();  // polymorphic call to area()
    }
    return total;
}

// Clone using covariant return types
std::vector<std::unique_ptr<Shape>> cloneScene(
    const std::vector<std::unique_ptr<Shape>>& scene) {
    std::vector<std::unique_ptr<Shape>> cloned;
    for (const auto& shape : scene) {
        cloned.push_back(
            std::unique_ptr<Shape>(shape->clone()));  // covariant return type
    }
    return cloned;
}

}  // namespace cad

// ========== Demo code ==========
int main() {
    using namespace cad;

    std::cout << "===== CAD Shape Drawing System =====\n" << std::endl;

    // Create the scene
    std::vector<std::unique_ptr<Shape>> scene;

    scene.push_back(std::make_unique<Circle>(100, 100, "red", 50));
    scene.push_back(std::make_unique<Rectangle>(0, 0, "blue", 200, 100));
    scene.push_back(std::make_unique<Triangle>(300, 200, "green", 60, 80, 100));
```

Case 3: Payment System (Polymorphism + Factory Pattern)
------------------------------------

[Real-life scenario] An e-commerce checkout page supports multiple payment methods (Alipay, WeChat Pay, bank card, credit card).
An abstract base class defines the payment interface, and each payment method overrides the payment logic.

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>
#include <iomanip>
#include <chrono>
#include <random>

// ====== Debug macro ======
#define PAY_DEBUG 1
#if PAY_DEBUG
    #define PAY_LOG(msg) std::cout << "[PAY] " << msg << std::endl
#else
    #define PAY_LOG(msg)
#endif

namespace payment {

// ====== Abstract base class: PaymentMethod ======
class PaymentMethod {
protected:
    std::string accountID;    // account identifier
    std::string accountName;  // account holder's name
    double balance;           // account balance
    static int totalTransactions;  // total number of transactions
    static double totalAmount;     // total transaction amount

public:
    PaymentMethod(const std::string& id, const std::string& name,
                  double bal)
        : accountID(id), accountName(name), balance(bal) {
        PAY_LOG("PaymentMethod created: " + name);
    }

    virtual ~PaymentMethod() {
        PAY_LOG("PaymentMethod destroyed: " + accountName);
    }

    // Pure virtual function -- the concrete implementation for each payment method
    virtual bool pay(double amount) = 0;

    // Pure virtual function -- get the payment method name
    virtual std::string getMethodName() const = 0;

    // Virtual function -- get the discount (some payment methods offer discounts)
    virtual double getDiscount(double amount) const {
        return 0.0;  // no discount by default
    }

    // Actual amount paid = original price - discount
    double getActualAmount(double amount) const {
        double discount = getDiscount(amount);
        return amount - discount;
    }

    // Non-virtual functions -- account information
    const std::string& getAccountID()   const { return accountID; }
    const std::string& getAccountName() const { return accountName; }
    double getBalance()                 const { return balance; }

    virtual void displayInfo() const {
        std::cout << std::left
                  << std::setw(15) << getMethodName()
                  << std::setw(20) << accountName
                  << "Balance: $" << std::fixed << std::setprecision(2)
                  << balance;
    }

    static int getTotalTransactions() { return totalTransactions; }
    static double getTotalAmount()    { return totalAmount; }
};

int PaymentMethod::totalTransactions = 0;
double PaymentMethod::totalAmount = 0.0;

// ====== Derived class: AliPay ======
class AliPay : public PaymentMethod {
public:
    AliPay(const std::string& id, const std::string& name, double bal)
        : PaymentMethod(id, name, bal) {
        PAY_LOG("AliPay account: " + name);
    }

    bool pay(double amount) override {
        std::cout << "[Alipay] ";
        if (amount > balance) {
            std::cout << "Payment failed! Insufficient balance ($" << balance
                      << " < $" << amount << ")" << std::endl;
            return false;
        }
        balance -= amount;
        totalTransactions++;
        totalAmount += amount;
        std::cout << "Payment successful! ¥" << amount
                  << " (balance: ¥" << balance << ")" << std::endl;
        return true;
    }

    std::string getMethodName() const override {
        return "Alipay";
    }

    double getDiscount(double amount) const override {
        // Alipay: 5 off on orders of 100 or more
        if (amount >= 100) return 5.0;
        return 0.0;
    }
};

// ====== Derived class: WeChatPay ======
class WeChatPay : public PaymentMethod {
private:
    int memberLevel;  // membership level (1-5)

public:
    WeChatPay(const std::string& id, const std::string& name,
              double bal, int level = 1)
        : PaymentMethod(id, name, bal), memberLevel(level) {
        PAY_LOG("WeChatPay account: " + name + " Lv." +
                std::to_string(level));
    }

    bool pay(double amount) override {
        std::cout << "[WeChat Pay] ";
        if (amount > balance) {
            std::cout << "Payment failed! Insufficient balance" << std::endl;
            return false;
        }
        balance -= amount;
        totalTransactions++;
        totalAmount += amount;
        std::cout << "Payment successful! ¥" << amount
                  << " (balance: ¥" << balance << ")" << std::endl;
        return true;
    }

    std::string getMethodName() const override {
        return "WeChat Pay";
    }

    double getDiscount(double amount) const override {
        // The higher the WeChat membership level, the bigger the discount
        double discount = memberLevel * 1.0;
        return (discount > amount * 0.1) ? amount * 0.1 : discount;
    }
};

// ====== Derived class: BankCard ======
class BankCard : public PaymentMethod {
private:
    std::string bankName;       // bank name
    std::string cardNumber;     // card number

public:
    BankCard(const std::string& id, const std::string& name,
             double bal, const std::string& bank, const std::string& card)
        : PaymentMethod(id, name, bal), bankName(bank), cardNumber(card) {
        PAY_LOG("BankCard: " + bank + " " + card.substr(0, 4) + "...");
    }

    bool pay(double amount) override {
        std::cout << "[" << bankName << "] ";
        if (amount > balance) {
            std::cout << "Payment failed! Insufficient balance" << std::endl;
            return false;
        }
        balance -= amount;
        totalTransactions++;
        totalAmount += amount;
        std::cout << "Bank card payment successful! ¥" << amount
                  << " (balance: ¥" << balance << ")" << std::endl;
        return true;
    }

    std::string getMethodName() const override {
        return "Bank Card(" + bankName + ")";
    }
};

// ====== Derived class: CreditCard ======
class CreditCard : public PaymentMethod {
private:
    double creditLimit;   // credit limit
    std::string bankName;

public:
    CreditCard(const std::string& id, const std::string& name,
               double bal, double limit, const std::string& bank)
        : PaymentMethod(id, name, bal), creditLimit(limit),
          bankName(bank) {
        PAY_LOG("CreditCard: " + bank +
                " limit=$" + std::to_string(limit));
    }

    bool pay(double amount) override {
        std::cout << "[Credit Card-" << bankName << "] ";
        // Available credit = balance + credit limit
        if (amount > balance + creditLimit) {
            std::cout << "Payment failed! Credit limit exceeded" << std::endl;
            return false;
        }
        // Pay from the balance first
        if (amount <= balance) {
            balance -= amount;
        } else {
            double fromBalance = balance;
            double fromCredit = amount - balance;
            balance = 0;
            creditLimit -= fromCredit;
            std::cout << "(using balance $" << fromBalance
                      << " + overdraft $" << fromCredit << ") ";
        }
        totalTransactions++;
        totalAmount += amount;
        std::cout << "Payment successful! ¥" << amount << std::endl;
        return true;
    }

    std::string getMethodName() const override {
        return "Credit Card(" + bankName + ")";
    }

    double getCreditLimit() const { return creditLimit; }
};

// ====== Factory function -- creates a payment method based on the user's choice ======
enum class PaymentType {
    ALIPAY,
    WECHAT,
    BANK_CARD,
    CREDIT_CARD
};

std::unique_ptr<PaymentMethod> createPayment(PaymentType type) {
    switch (type) {
        case PaymentType::ALIPAY:
            return std::make_unique<AliPay>("ALI001", "Alice", 5000.0);
        case PaymentType::WECHAT:
            return std::make_unique<WeChatPay>("WX001", "Bob", 3000.0, 3);
        case PaymentType::BANK_CARD:
            return std::make_unique<BankCard>(
                "BC001", "Charlie", 8000.0,
                "ICBC", "6222034567890123");
        case PaymentType::CREDIT_CARD:
            return std::make_unique<CreditCard>(
                "CC001", "Diana", 2000.0, 10000.0, "China Merchants Bank");
        default:
            return nullptr;
    }
}

// ====== Process a payment ======
void processPayment(PaymentMethod& method, double amount) {
    std::cout << "\n--- Processing payment ---" << std::endl;
    std::cout << "Payment method: " << method.getMethodName() << std::endl;
    std::cout << "Order amount: ¥" << amount << std::endl;

    double discount = method.getDiscount(amount);
    if (discount > 0) {
        std::cout << "Discount: -¥" << discount << " (applied "
                  << method.getMethodName() << " promotion)" << std::endl;
    }

    double actualAmount = method.getActualAmount(amount);
    std::cout << "Amount due: ¥" << actualAmount << std::endl;

    bool success = method.pay(actualAmount);
    if (success) {
        std::cout << "\xE2\x9C\x85 Payment complete!" << std::endl;
    } else {
        std::cout << "\xE2\x9D\x8C Payment failed!" << std::endl;
    }
}
```

Case 4: Media Player Framework (Interface + Template Method Pattern + Virtual Function Default Argument Pitfall)
------------------------------------

[Real-life scenario] A universal media player. An interface defines the player's behavior,
showcasing the Template Method pattern and demonstrating the pitfall of default arguments in virtual functions.

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>
#include <iomanip>

// ====== Debug macro ======
#define MEDIA_DEBUG 1
#if MEDIA_DEBUG
    #define MEDIA_LOG(msg) std::cout << "[MEDIA] " << msg << std::endl
#else
    #define MEDIA_LOG(msg)
#endif

namespace media {

// ====== Playback state ======
enum class PlayState {
    STOPPED,
    PLAYING,
    PAUSED
};

// ====== Abstract interface: IMediaPlayer ======
class IMediaPlayer {
protected:
    std::string title;
    std::string artist;
    double duration;      // seconds
    PlayState state;

public:
    IMediaPlayer(const std::string& t, const std::string& a, double dur)
        : title(t), artist(a), duration(dur), state(PlayState::STOPPED) {
        MEDIA_LOG("Media loaded: " + t);
    }

    // Virtual destructor -- an interface class must have one!
    virtual ~IMediaPlayer() {
        MEDIA_LOG("Media unloaded: " + title);
    }

    // Pure virtual functions -- low-level playback logic that subclasses must implement
    virtual void doPlay() = 0;
    virtual void doPause() = 0;
    virtual void doStop() = 0;
    virtual void doSeek(double position) = 0;

    // Pure virtual functions -- media type
    virtual std::string getMediaType() const = 0;
    virtual std::string getFormatInfo() const = 0;

    // ====== Template Method pattern: the base class implements the algorithm skeleton and calls the derived classes' pure virtual functions ======
    // Note: a default argument is deliberately used in the virtual function play here to demonstrate the pitfall!
    virtual bool play(int volume = 50) {  // default argument!
        state = PlayState::PLAYING;
        doPlay();
        std::cout << "  Volume: " << volume << "%" << std::endl;
        return true;
    }

    bool pause() {
        if (state != PlayState::PLAYING) return false;
        state = PlayState::PAUSED;
        doPause();
        return true;
    }

    bool stop() {
        if (state == PlayState::STOPPED) return false;
        state = PlayState::STOPPED;
        doStop();
        return true;
    }

    bool seek(double position) {
        if (position < 0 || position > duration) return false;
        doSeek(position);
        return true;
    }

    // Non-virtual functions
    const std::string& getTitle() const { return title; }
    double getDuration() const { return duration; }
    PlayState getState() const { return state; }

    void displayInfo() const {
        std::cout << std::left
                  << "[" << std::setw(12) << getMediaType() << "] "
                  << std::setw(25) << title
                  << " Duration: " << std::setw(6) << duration << "s"
                  << " Format: " << getFormatInfo()
                  << std::endl;
    }
};

// ====== Demonstrate the virtual function default argument pitfall ======
void demonstrateDefaultParamTrap() {
    std::cout << "\n===== Virtual Function Default Argument Pitfall Demo =====" << std::endl;

    StreamingPlayer stream("Online Music", "Various", 240, "https://music.example.com/song1", 10);

    // Call through a base class pointer
    IMediaPlayer* basePtr = &stream;
    basePtr->play();   // Output: is the volume 80% or 50%?
                        // Answer: 50%! Because default arguments are statically bound!
                        // The default argument of play in the base class is 50

    // Call through a derived class pointer
    StreamingPlayer* derivedPtr = &stream;
    derivedPtr->play();  // Output: volume 80% (uses the derived class's default argument)

    std::cout << "\nPitfall explained:" << std::endl;
    std::cout << "  basePtr->play()     -> volume 50% (uses the base class default argument)" << std::endl;
    std::cout << "  derivedPtr->play()  -> volume 80% (uses the derived class default argument)" << std::endl;
    std::cout << "  Virtual functions bind dynamically, but default arguments bind statically!" << std::endl;
}
```

```cpp
#include <iostream>

// ====== Combining knowledge from the first 6 chapters ======
// Chapter 2: debug macro
#define UI_DEBUG 1

    #define UI_LOG(msg) std::cout << "[UI] " << msg << std::endl

    #define UI_LOG(msg)

namespace ui {

// ====== Point ======
struct Point {
    int x, y;
    Point(int xVal = 0, int yVal = 0) : x(xVal), y(yVal) { }
};

// ====== Rectangular region ======
struct Rect {
    int x, y, width, height;
    Rect(int xVal = 0, int yVal = 0, int w = 0, int h = 0)
        : x(xVal), y(yVal), width(w), height(h) {}

    bool contains(const Point& p) const {
        return p.x >= x && p.x <= x + width &&
               p.y >= y && p.y <= y + height;
    }
};

// ====== Abstract base class: Widget ======
class Widget {
protected:
    std::string id;
    Rect bounds;
    bool visible;
    bool enabled;
    std::string text;
    std::string backgroundColor;
    std::string textColor;

    static int widgetCount;

public:
    Widget(const std::string& widgetId, const Rect& b, const std::string& t)
        : id(widgetId), bounds(b), visible(true), enabled(true), text(t),
          backgroundColor("#FFFFFF"), textColor("#000000") {
        widgetCount++;
        UI_LOG("Widget created: " + id);
    }

    // ====== Virtual destructor ======
    virtual ~Widget() {
        widgetCount--;
        UI_LOG("Widget destroyed: " + id);
    }

    // ====== Pure virtual functions ======
    virtual void render() const = 0;
    virtual std::string getType() const = 0;

    // ====== Virtual functions -- overridable default implementations ======
    virtual void onClick(const Point& p) {
        std::cout << "  [" << id << "] clicked at ("
                  << p.x << "," << p.y << ")" << std::endl;
    }

    virtual void onHover(const Point& p) {
        std::cout << "  [" << id << "] hover at ("
                  << p.x << "," << p.y << ")" << std::endl;
    }

    virtual void onDoubleClick(const Point& p) {
        std::cout << "  [" << id << "] double-clicked at ("
                  << p.x << "," << p.y << ")" << std::endl;
    }

    virtual void onKeyPress(char key) {
        std::cout << "  [" << id << "] key pressed: '" << key << "'"
                  << std::endl;
    }

    // ====== Non-virtual functions ======
    void show() { visible = true; }
    void hide() { visible = false; }
    void enable() { enabled = true; }
    void disable() { enabled = false; }
    bool isVisible() const { return visible; }
    bool isEnabled() const { return enabled; }

    void move(int dx, int dy) {
        bounds.x += dx;
        bounds.y += dy;
    }

    void resize(int w, int h) {
        bounds.width = w;
        bounds.height = h;
    }

    const std::string& getID() const { return id; }
    const Rect& getBounds() const { return bounds; }
    const std::string& getText() const { return text; }

    void setText(const std::string& t) { text = t; }
    void setColors(const std::string& bg, const std::string& fg) {
        backgroundColor = bg;
        textColor = fg;
    }

    void displayInfo() const {
        std::cout << std::left
                  << std::setw(12) << getType()
                  << std::setw(15) << id
                  << " @(" << std::setw(3) << bounds.x
                  << "," << std::setw(3) << bounds.y << ") "
                  << std::setw(5) << bounds.width
                  << "x" << std::setw(5) << bounds.height
                  << " \"" << text << "\""
                  << std::endl;
    }

    static int getWidgetCount() { return widgetCount; }
};

int Widget::widgetCount = 0;

            if (selectedIndex >= 0) {
                std::cout << "\xF0\x9F\x93\x8B ComboBox selected: "
                          << items[selectedIndex] << std::endl;
            }
        }
    }

    void selectItem(size_t index) {
        if (index < items.size()) {
            selectedIndex = index;
            text = items[index];
        }

enum class WidgetType {
    BUTTON,
    TEXTBOX,
    COMBOBOX,
    LABEL,
    SLIDER
};

std::unique_ptr<Widget> createWidget(WidgetType type,
    const std::string& id, const Rect& bounds = Rect(0,0,100,30)) {
    switch (type) {
        case WidgetType::BUTTON:
            return std::make_unique<Button>(id, bounds, "Click Me");
        case WidgetType::TEXTBOX:
            return std::make_unique<TextBox>(id, bounds, "Enter text...");
        case WidgetType::COMBOBOX:
            return std::make_unique<ComboBox>(id, bounds);
        case WidgetType::LABEL:
            return std::make_unique<Label>(id, bounds, "Welcome!");
        case WidgetType::SLIDER:
            return std::make_unique<Slider>(id, bounds, 0, 100, 50);
        default:
            return nullptr;
    }
}

// ====== Application window ======
class Application {
private:
    std::vector<std::unique_ptr<Widget>> widgets;

public:
    void addWidget(std::unique_ptr<Widget> widget) {
        widgets.push_back(std::move(widget));
    }

    void render() const {
        std::cout << "\n===== Rendering UI =====" << std::endl;
        for (const auto& w : widgets) {
            if (w->isVisible()) {
                w->render();
            }
        }
    }

    void handleClick(const Point& p) {
        std::cout << "\n===== Handling Click Event =====" << std::endl;
        for (auto& w : widgets) {
            if (w->isVisible() && w->isEnabled() &&
                w->getBounds().contains(p)) {
                w->onClick(p);

                // Use dynamic_cast for type checks
                if (dynamic_cast<Button*>(w.get())) {
                    std::cout << "  -> Button event triggered" << std::endl;
                } else if (dynamic_cast<ComboBox*>(w.get())) {
                    std::cout << "  -> Expand/select event triggered" << std::endl;
                }
            }
        }
    }

    void handleHover(const Point& p) {
        for (auto& w : widgets) {
            if (w->isVisible() && w->isEnabled() &&
                w->getBounds().contains(p)) {
                w->onHover(p);
            }
        }
    }

    void handleKeyPress(char key) {
        for (auto& w : widgets) {
            if (w->isVisible() && w->isEnabled()) {
                // dynamic_cast checks whether it is a TextBox
                if (auto* textBox = dynamic_cast<TextBox*>(w.get())) {
                    textBox->onKeyPress(key);
                }
            }
        }
    }

    void printWidgetTree() const {
        std::cout << "\n===== Widget Tree =====" << std::endl;
        for (const auto& w : widgets) {
            w->displayInfo();
        }
    }

    Widget* findWidget(const std::string& id) {
        for (auto& w : widgets) {
            if (w->getID() == id) return w.get();
        }
        return nullptr;
    }

    size_t widgetCount() const { return widgets.size(); }
};

}  // namespace ui
```

Exercise: Design an "Employee Workflow System" Employee
======================================================

[Real-life scenario]
A software company needs to develop an internal workflow management system. Different types of employees
(developers, designers, managers, salespeople) have different job duties and salary calculation methods.

[Requirements]

1. Abstract base class: Employee
   Pure virtual functions:
   - work() const = 0:                   simulate a day's work
   - getRole() const = 0:                return the job title
   - calculateSalary() const = 0:        calculate the monthly salary
   Protected member variables:
   - name, employeeID, baseSalary, yearsOfService
   A virtual destructor!

2. Derived classes:
   (a) Developer
       New attributes: programmingLanguages (std::vector<std::string>)
                isSenior (bool)
       work(): prints "Writing code, debugging programs, attending code reviews"
       calculateSalary(): senior developers get a 30% raise on base salary

   (b) Designer
       New attributes: designTools (std::vector<std::string>)
                portfolioRating (double, 1-5)
       work(): prints "Designing interfaces, building prototypes, designing interactions"
       calculateSalary(): add a bonus based on the portfolio rating

   (c) Manager
       New attributes: teamMembers (std::vector<std::shared_ptr<Employee>>)
                department (std::string)
       work(): prints "Holding meetings, approving requirements, making plans"
       calculateSalary(): base salary + management allowance + team performance bonus
       Provides: addTeamMember(), removeTeamMember() to manage team members

   (d) SalesPerson
       New attributes: monthlySales (double), commissionRate (double)
       work(): prints "Visiting clients, writing proposals, negotiating and closing deals"
       calculateSalary(): base salary + sales commission

3. Global function:
   processPayroll(const std::vector<Employee*>& employees):
      Iterate over all employees and print each employee's role, name, and salary
      Calculate and print the total payroll

4. Requirements for main:
   - Create an array of base class pointers (vector<Employee*> or vector<unique_ptr<Employee>>)

I. In-Depth Analysis of Virtual Function Performance
------------------------------------

```cpp
#include <iostream>
#include <chrono>
#include <vector>

// Measuring the real overhead of virtual function calls
class Base {
public:
    virtual int compute(int x) { return x * 2; }
};

class Derived : public Base {
public:
    int compute(int x) override { return x * 3; }
};

// Non-virtual version (for comparison)
class StaticBase {
public:
    int compute(int x) { return x * 2; }
};

// Sources of virtual function overhead:
// 1. Indirect jump (at least one extra pointer dereference)
// 2. Cannot be inlined (the compiler doesn't know the runtime type)
// 3. Possible cache misses (the vtable is not on the same cache line)
// 4. Branch mispredictions (when there are multiple derived classes)

// But on modern CPUs, unless you are in an extremely hot tight loop, virtual function overhead is usually <5%
// If performance is critical, consider these alternatives:
//   a. CRTP (Curiously Recurring Template Pattern) -- covered in Chapter 8
//   b. std::variant + std::visit -- C++17
//   c. Type tags + switch (when the set of types is limited)

// Optimization advice:
// 1. Don't avoid polymorphism for the sake of performance -- write maintainable code first
// 2. Use a profiler to find the real bottlenecks
// 3. Only optimize once you've confirmed virtual functions are the bottleneck
```

II. A Quick Tour of Polymorphic Design Patterns
------------------------------------

[Template Method Pattern]
The base class defines the algorithm skeleton, and derived classes override specific steps:

```cpp
class DocumentGenerator {
public:
    void generate() {                // template method -- not overridable (final)
        openDocument();              // 1. open the document
        writeHeader();               // 2. write the header
        writeBody();                 // 3. write the body
        writeFooter();               // 4. write the footer
        closeDocument();             // 5. close the document
    }
protected:
    virtual void writeHeader() = 0;  // subclasses implement different headers
    virtual void writeBody() = 0;    // subclasses implement different bodies
    virtual void writeFooter() = 0;  // subclasses implement different footers
    void openDocument()  { /* common implementation */ }
    void closeDocument() { /* common implementation */ }
};

class PDFGenerator : public DocumentGenerator {
    void writeHeader() override { /* PDF header */ }
    void writeBody()   override { /* PDF body */ }
    void writeFooter() override { /* PDF footer */ }
};
```

[Factory Method Pattern]

```cpp
class Creator {
public:
    virtual std::unique_ptr<Product> createProduct() = 0;
    // Factory method for creating products -- subclasses decide the concrete product type
};

class ConcreteCreatorA : public Creator {
    std::unique_ptr<Product> createProduct() override {
        return std::make_unique<ConcreteProductA>();
    }
};
```

[Strategy Pattern]
Encapsulate algorithms as classes and switch between them through composition and polymorphism:

```cpp
class SortStrategy {
public:
    virtual void sort(std::vector<int>& data) = 0;
    virtual ~SortStrategy() = default;
};

class QuickSort : public SortStrategy {
    void sort(std::vector<int>& data) override { /* quicksort */ }
};

class MergeSort : public SortStrategy {
    void sort(std::vector<int>& data) override { /* merge sort */ }
};

class Sorter {
    std::unique_ptr<SortStrategy> strategy;
public:
    void setStrategy(std::unique_ptr<SortStrategy> s) {
        strategy = std::move(s);
    }
    void sort(std::vector<int>& data) {
        strategy->sort(data);  // polymorphic call
    }
};
```

III. Common Virtual Function Interview Questions
------------------------------------

[Question 1] When is the virtual function table (vtable) created?
Answer: The vtable is static data generated at compile time and stored in the read-only data segment (.rodata).
   Each class with virtual functions gets one vtable at compile time, shared by all objects of that class.

[Question 2] When is the vptr initialized?
Answer: It is initialized while the constructor runs. Specifically:
   1. Entering Base's constructor -> vptr points to Base's vtable -> Base's constructor body runs
   2. Entering Derived's constructor -> vptr is updated to point to Derived's vtable -> Derived's constructor body runs
   This explains why virtual functions are statically bound in constructors/destructors.

[Question 3] Why should the destructor be virtual?
Answer: When a derived object is deleted through a base class pointer and the destructor is not virtual,
   the compiler only calls the base class destructor, so resources specific to the derived class are not released, causing a memory leak.
   On delete basePtr, the compiler finds the correct destructor address in the vtable through the vptr.

[Question 4] Can a pure virtual function have an implementation?
Answer: Yes. The declaration and the implementation of a pure virtual function are separate:
   virtual void func() = 0;           // declaration (interface)
   void Base::func() { /* impl */ }   // implementation (optional)
   The implementation of a pure virtual function usually provides default behavior, which derived classes call explicitly via Base::func().

[Question 5] Why can't a constructor be virtual?
Answer: Virtual function calls depend on the vptr, and the vptr is only initialized while the constructor runs.
   If the constructor were virtual, the vptr would not yet be set up when constructing the object itself, so there would be no way to decide which version to call.
   This forms a chicken-and-egg paradox.

IV. Applying SOLID Principles to Polymorphic Design
------------------------------------

One of the most important principles in object-oriented design is the "Open-Closed Principle (OCP)":
open for extension, closed for modification. Polymorphism is the key mechanism for achieving OCP.

```cpp
// ❌ Violates OCP -- this function must be modified every time a new shape is added
double calculateArea(const std::string& type, double param1, double param2) {
    if (type == "circle") return 3.14 * param1 * param1;
    else if (type == "rectangle") return param1 * param2;
    else if (type == "triangle") return 0.5 * param1 * param2;
    // Adding a new shape -> this function must be modified!
    return 0;
}

// ✅ Follows OCP -- through polymorphism, adding a shape only requires a new class, no changes to existing code
class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
    double radius;
public:
    Circle(double r) : radius(r) {}
    double area() const override { return 3.14 * radius * radius; }
};

// Adding an ellipse -- just add a new class, without modifying any existing code
class Ellipse : public Shape {
    double a, b;  // semi-major axis, semi-minor axis
public:
    Ellipse(double ma, double mb) : a(ma), b(mb) {}
    double area() const override { return 3.14 * a * b; }
};
```

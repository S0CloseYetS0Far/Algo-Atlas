[Chapter Overview]
Signals are an asynchronous inter-process notification mechanism provided by the
operating system. Although signal handling is not used as widely in C++ as the
topics of previous chapters, it is essential knowledge for writing daemons,
server programs, and CLI tools. Starting from the kernel's signal mechanism, this
chapter gives a complete tour of the C++ signal handling interfaces.

I. Basic signal() Example

---------------------------------------------------------------
// ---- Basic example: catching SIGINT (Ctrl+C) ----
#include <iostream>
#include <csignal>
#include <unistd.h>

// Signal handler
volatile sig_atomic_t g_keepRunning = 1;

void signalHandler(int signum) {
    std::cout << "\nReceived signal: " << signum << " (Ctrl+C)" << std::endl;
    std::cout << "Exiting safely..." << std::endl;
    g_keepRunning = 0;  // Set the exit flag
}

int main() {
    // Register the signal handler
    signal(SIGINT, signalHandler);

    std::cout << "Program running... press Ctrl+C to exit" << std::endl;

    int iteration = 0;
    while (g_keepRunning) {
        std::cout << "Iteration " << ++iteration << std::endl;
        sleep(1);  // Simulate work
    }

    std::cout << "Program exited safely" << std::endl;
    return 0;
}

II. The OS Signal Mechanism -- Low-Level Principles

1. What is a signal?

   A signal is an asynchronous notification mechanism for inter-process
   communication (IPC) on UNIX/Linux systems. It is similar to a "software
   interrupt": one process (or the kernel) sends a signal to another process,
   and the target process handles that signal at an appropriate moment.

   The three key stages of a signal:
   ┌──────────────┬──────────────────────────────────────────────┐
   │ Stage        │ Description                                  │
   ├──────────────┼──────────────────────────────────────────────┤
   │ Generate     │ The kernel or another process sends a signal │
   │ Pending      │ Sent, but not yet handled by the target      │
   │ Deliver      │ The target process runs the signal handler   │
   └──────────────┴──────────────────────────────────────────────┘

2. How the kernel sends a signal

   When the kernel sends a signal to a process, these data structures are involved:

   ┌─────────────────────────────────────────────────────────┐
   │  Process task_struct (process descriptor in the kernel) │
   ├─────────────────────────────────────────────────────────┤
   │  struct task_struct {                                   │
   │      ...                                                │
   │      struct signal_struct *signal;  // shared sig desc  │
   │      struct sighand_struct *sighand; // handler table   │
   │      sigset_t blocked;       // blocked (masked) set    │
   │      struct sigpending pending; // private pending set  │
   │      ...                                                │
   │  };                                                     │
   │                                                         │
   │  struct sigpending {                                    │
   │      struct list_head list;  // pending signal list     │
   │      sigset_t signal;        // pending signal bitmap   │
   │  };                                                     │
   └─────────────────────────────────────────────────────────┘

   The sending process (using kill(pid, SIGINT) as an example):

   Step 1: The kernel verifies the sender's permissions (same user or root).
   Step 2: In the target process's task_struct->pending.signal bitmap,
           the bit corresponding to SIGINT is set.
   Step 3: A signal info node is appended to the pending.list linked list.
   Step 4: If the target process is sleeping, it is woken up (if it is in
           TASK_INTERRUPTIBLE).
   Step 5: When the target process is scheduled to run, before returning to
           user mode, the kernel checks the pending.signal bitmap.
   Step 6: If there is a pending signal that is not blocked, the kernel sets up
           a user-mode stack frame so that the process runs the signal handler
           when it returns to user mode.
   Step 7: After the signal handler finishes, the sigreturn system call
           restores the interrupted normal execution.

3. The execution context of a signal handler

   The signal handler runs in user mode, but it "interrupts" the normal flow
   of execution of the process:

   Normal execution flow:
   main() -> funcA() -> funcB() -> [interrupted by signal]
                                     ↓
                              run the signal handler
                                     ↓
                              resume executing funcB()

   Key restrictions:
   - The signal handler is invoked "asynchronously" (not in the normal call chain)
   - It uses the process's user stack (or an alternate signal stack, if
     sigaltstack has been set up)
   - Very few functions can be safely called from a signal handler

4. Async-Signal-Safe Functions

   Because a signal handler can interrupt normal code at any moment (including
   halfway through library functions such as malloc() or printf()), re-entering
   these functions may cause deadlock (e.g. malloc() holds an internal lock; if
   the signal handler calls malloc again, it deadlocks).

   The POSIX standard defines a set of "async-signal-safe" functions that can be
   safely called from a signal handler. Common safe functions include:

   ┌───────────────────────────────────────────────────────┐
   │ _Exit(), _exit()        Terminate the process         │
   │ abort()                 Abnormal termination          │
   │ signal()                Register a signal handler     │
   │ write()                 Write to a file descriptor    │
   │ read()                  Read from a file descriptor   │
   │ open(), close()         Open/close a file             │
   │ fork(), exec()          Create/execute a process      │
   │ waitpid()               Wait for a child process      │
   │ kill(), raise()         Send a signal                 │
   │ alarm()                 Set an alarm                  │
   │ sleep()                 Sleep                         │
   └───────────────────────────────────────────────────────┘

   Typical examples of unsafe functions (must NOT be called in a signal handler):
   - printf / cout (use buffer locks internally)
   - malloc / new (the memory allocator has global locks)
   - exit() (runs global destructors, involving many locks)
   - std::string operations (may allocate memory)

5. Reliable vs Unreliable Signals

   The signal mechanism of early UNIX was "unreliable":
   - Signals could be lost (multiple identical signals merged into one)
   - The handler was automatically reset to the default after each invocation
   - Signals could not be blocked/masked

   Modern POSIX signals are "reliable":
   - Real-time signals (SIGRTMIN~SIGRTMAX) are queued and are not lost
   - Signals can be blocked/masked with sigprocmask
   - sigaction replaces signal() and behaves more predictably

   However, the C++ standard library signal() function is based on the early
   unreliable signal model. In real-world development, if you need reliable
   signal handling, use POSIX sigaction.

6. Signal handlers and volatile sig_atomic_t

   sig_atomic_t is an integer type whose reads and writes are atomic
   (cannot be interrupted by a signal). It is the only safe way for a signal
   handler to communicate with the main program.

   Note: since C++11, volatile is no longer a thread-safety mechanism,
   but volatile sig_atomic_t has special semantics in signal handling:
   - volatile tells the compiler not to optimize away accesses to the variable
   - sig_atomic_t guarantees that reads/writes are not interrupted by signals

   volatile sig_atomic_t flag = 0;

   void handler(int sig) {
       flag = 1;  // Safe: atomic write
   }

   int main() {
       signal(SIGINT, handler);
       while (!flag) {
           // Safe: atomic read
       }
   }

8. sigaction vs signal -- reliable POSIX signal handling

   The C standard library signal() behaves inconsistently across UNIX systems
   (some reset the handler to the default, some don't). POSIX provides
   sigaction() for more precise control:

   ---------------------------------------------------------------
   #include <iostream>
   #include <csignal>
   #include <cstring>
   #include <unistd.h>

   volatile sig_atomic_t g_exitFlag = 0;

   // Signal handler used with sigaction
   void sigactionHandler(int signum, siginfo_t* info, void* context) {
       char msg[128];
       int len = snprintf(msg, sizeof(msg),
           "[sigaction] signal %d from PID=%d (UID=%d)\n",
           signum,
           info ? info->si_pid : -1,
           info ? info->si_uid : -1);
       write(STDOUT_FILENO, msg, len);

       g_exitFlag = 1;
   }

   int main() {
       struct sigaction sa;
       memset(&sa, 0, sizeof(sa));
       sa.sa_sigaction = sigactionHandler;  // Use the extended handler
       sa.sa_flags = SA_SIGINFO;             // Enable extra info
       sigemptyset(&sa.sa_mask);             // Do not mask extra signals

       // Register
       sigaction(SIGINT, &sa, nullptr);
       sigaction(SIGTERM, &sa, nullptr);

       std::cout << "PID=" << getpid() << std::endl
                 << "sigaction provides richer information than signal():" << std::endl
                 << " - Can obtain the sender's PID and UID" << std::endl
                 << " - Can specify which signals to mask during handling" << std::endl
                 << " - Can control SA_RESTART (auto-restart interrupted syscalls)" << std::endl
                 << " - Behavior is consistent across UNIX systems" << std::endl;

       while (!g_exitFlag) {
           std::cout << "." << std::flush;
           sleep(1);
       }

       std::cout << "\nExited safely" << std::endl;
       return 0;
   }
   ---------------------------------------------------------------

   signal() vs sigaction() comparison:
   ┌──────────────────────┬─────────────────┬──────────────────────┐
   │ Feature              │ signal()        │ sigaction()          │
   ├──────────────────────┼─────────────────┼──────────────────────┤
   │ Portability          │ C++ standard    │ POSIX                │
   │ Mask during handling │ Not controllable│ Precisely settable   │
   │ Sender info          │ Not supported   │ Via SA_SIGINFO       │
   │ Auto reset           │ Inconsistent    │ Explicit control     │
   │ Restart syscalls     │ Platform-dep.   │ SA_RESTART controls  │
   │ Real-time signals    │ Not supported   │ Supported            │
   └──────────────────────┴─────────────────┴──────────────────────┘

9. Signal masking and blocking

   A process can temporarily "block" (mask) certain signals. A blocked signal
   stays in the "pending" state and is delivered only after it is unblocked:

   ---------------------------------------------------------------
   #include <iostream>
   #include <csignal>
   #include <cstring>
   #include <unistd.h>

   volatile sig_atomic_t g_interrupted = 0;

   void criticalHandler(int s) {
       write(STDOUT_FILENO, "Signal handled outside critical section\n", 40);
       g_interrupted = 1;
   }

   int main() {
       signal(SIGINT, criticalHandler);

       // Define the signal set
       sigset_t newMask, oldMask;
       sigemptyset(&newMask);
       sigaddset(&newMask, SIGINT);    // Block SIGINT

       std::cout << "PID=" << getpid() << std::endl;

       // Critical section: block SIGINT so it cannot interrupt us
       std::cout << "Entering critical section (SIGINT blocked)..." << std::endl;
       sigprocmask(SIG_BLOCK, &newMask, &oldMask);

       // Simulate a critical operation (data update that must not be interrupted)
       for (int i = 0; i < 3; i++) {
           std::cout << "  Critical operation " << (i+1) << std::endl;
           sleep(1);
       }

       // Check whether a SIGINT was blocked
       sigset_t pending;
       sigpending(&pending);
       if (sigismember(&pending, SIGINT)) {
           std::cout << "Blocked SIGINT detected; it will be handled after leaving the critical section"
                     << std::endl;
       }

       // Leave the critical section and restore the original signal mask
       std::cout << "Leaving critical section (SIGINT can be delivered)" << std::endl;
       sigprocmask(SIG_SETMASK, &oldMask, nullptr);

       // The previously blocked signal is now delivered automatically

       sleep(1);
       std::cout << "Program finished" << std::endl;
       return 0;
   }
   ---------------------------------------------------------------

   Use cases for signal blocking:
   - Protecting critical operations that must not be interrupted, like bank transfers
   - Preventing log writes from being interrupted by a signal and corrupting data
   - Preventing re-entry (recursive invocation) of the signal handler, which can
     overflow the stack

I. The <csignal> Header and the signal() Function

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <unistd.h>

// Multiple signal handlers
volatile sig_atomic_t sigintReceived = 0;
volatile sig_atomic_t sigtermReceived = 0;
volatile sig_atomic_t sigusr1Received = 0;

void handleSIGINT(int signum) {
    // Only async-signal-safe functions may be called safely
    const char msg[] = "Received SIGINT\n";
    write(STDOUT_FILENO, msg, sizeof(msg) - 1);
    sigintReceived = 1;
}

void handleSIGTERM(int signum) {
    const char msg[] = "Received SIGTERM\n";
    write(STDOUT_FILENO, msg, sizeof(msg) - 1);
    sigtermReceived = 1;
}

void handleSIGUSR1(int signum) {
    const char msg[] = "Received SIGUSR1\n";
    write(STDOUT_FILENO, msg, sizeof(msg) - 1);
    sigusr1Received = 1;
}

int main() {
    std::cout << "Process PID: " << getpid() << std::endl;

    // Register multiple signal handlers
    signal(SIGINT, handleSIGINT);    // Ctrl+C
    signal(SIGTERM, handleSIGTERM);  // the kill command
    signal(SIGUSR1, handleSIGUSR1);  // user-defined signal 1

    // Ignore a signal
    signal(SIGHUP, SIG_IGN);         // Ignore the hangup signal

    // Restore the default handling
    // signal(SIGINT, SIG_DFL);

    std::cout << "Waiting for signals... (test with kill -USR1 " << getpid()
              << ")" << std::endl;

    int count = 0;
    while (!sigintReceived && !sigtermReceived && count < 30) {
        std::cout << "." << std::flush;
        sleep(1);
        count++;

        // Handle SIGUSR1 (the flag was set in the signal handler)
        if (sigusr1Received) {
            sigusr1Received = 0;
            std::cout << "\n[main] Handling SIGUSR1" << std::endl;
        }
    }

    std::cout << "\nProgram exiting" << std::endl;
    return 0;
}

II. The raise() Function -- Sending a Signal to Yourself

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <cstdlib>

volatile sig_atomic_t alarmFlag = 0;

void alarmHandler(int signum) {
    alarmFlag = 1;
    write(STDOUT_FILENO, "[ALARM]\n", 8);
}

int main() {
    signal(SIGALRM, alarmHandler);

    std::cout << "Setting a 3-second timer..." << std::endl;
    std::cout << "raise(SIGALRM) triggers the signal immediately" << std::endl;

    // raise(): immediately send a signal to this process
    raise(SIGALRM);  // Equivalent to kill(getpid(), SIGALRM)

    // alarm(): have the kernel send SIGALRM after 3 seconds
    alarm(3);

    while (!alarmFlag) {
        std::cout << "Waiting for alarm..." << std::endl;
        sleep(1);
    }

    std::cout << "Alarm fired" << std::endl;
    alarm(0);  // Cancel the timer
    return 0;
}

IV. The sig_atomic_t Type and volatile

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <unistd.h>
#include <cstring>

// Correct usage patterns for sig_atomic_t

// 1. A simple flag (the safest approach)
volatile sig_atomic_t simpleFlag = 0;

void simpleHandler(int signum) {
    simpleFlag = 1;  // Atomic operation, signal-safe
}

// 2. Counting signals (note: signals may still be lost due to merging)
volatile sig_atomic_t signalCount = 0;

void countHandler(int signum) {
    signalCount++;  // Atomic on most platforms, but no guarantee nothing is lost
}

// 3. Multiple flags
volatile sig_atomic_t flags[4] = {0};

void multiHandler(int signum) {
    switch (signum) {
        case SIGINT:  flags[0] = 1; break;
        case SIGTERM: flags[1] = 1; break;
        case SIGUSR1: flags[2] = 1; break;
        case SIGUSR2: flags[3] = 1; break;
    }
}

int main() {
    signal(SIGUSR1, simpleHandler);
    signal(SIGUSR2, multiHandler);

    // Correct checking pattern: the main loop checks the flag periodically
    std::cout << "PID: " << getpid() << std::endl;
    std::cout << "Send a signal to test: kill -USR1 " << getpid() << std::endl;
    std::cout << "The main loop checks the flag every 100ms" << std::endl;

    for (int i = 0; i < 20; ++i) {
        // Check the flag (safe: reading sig_atomic_t is atomic)
        if (simpleFlag) {
            simpleFlag = 0;  // Reset the flag
            std::cout << "[main loop] SIGUSR1 detected" << std::endl;
            // Safe to do real handling here (outside the signal handler)
        }

        usleep(100000);  // 100ms
    }

    std::cout << "Demo finished" << std::endl;
    return 0;
}

V. Process Termination Functions: abort(), exit(), atexit(), _Exit()

---------------------------------------------------------------
#include <iostream>
#include <cstdlib>
#include <csignal>

// Cleanup functions registered with atexit
void cleanup1() {
    std::cout << "[cleanup 1] Closing log file" << std::endl;
}

void cleanup2() {
    std::cout << "[cleanup 2] Releasing database connection" << std::endl;
}

void cleanup3() {
    std::cout << "[cleanup 3] Saving user data" << std::endl;
}

// Signal handler (to demonstrate abort raising SIGABRT)
void sigabrtHandler(int signum) {
    std::cout << "[signal handler] Received SIGABRT" << std::endl;
    // Note: the SIGABRT raised by abort() terminates the program even after
    // the signal handler returns (the C standard requires abort() to terminate the process)
}

int main() {
    // Register atexit functions (called in reverse order of registration on exit)
    atexit(cleanup1);
    atexit(cleanup2);
    atexit(cleanup3);

    std::cout << "===== Process Termination Functions Demo =====" << std::endl;

    // 1. exit() -- normal termination
    // exit(0);  // Calls the atexit functions and global object destructors

    // 2. abort() -- abnormal termination
    // abort();  // Does not call atexit functions; sends SIGABRT

    // 3. _Exit() -- immediate termination
    // _Exit(0);  // Does not call atexit functions; does not flush buffers

    // 4. signal() + raise() -- termination via signal
    signal(SIGABRT, sigabrtHandler);

    std::cout << "\nChoose an exit method:" << std::endl;
    std::cout << "1: exit(0) -- normal exit (calls atexit)" << std::endl;
    std::cout << "2: abort() -- abnormal exit (sends SIGABRT)" << std::endl;
    std::cout << "3: _Exit(0) -- immediate exit (does not call atexit)" << std::endl;
    std::cout << "4: raise(SIGTERM) -- send a termination signal" << std::endl;

    int choice = 1;  // The demo defaults to exit(0)

    switch (choice) {
        case 1:
            std::cout << "\n--- Using exit(0) ---" << std::endl;
            exit(0);
            break;
        case 2:
            std::cout << "\n--- Using abort() ---" << std::endl;
            abort();
            break;
        case 3:
            std::cout << "\n--- Using _Exit(0) ---" << std::endl;
            _Exit(0);
            break;
        case 4:
            std::cout << "\n--- Using raise(SIGTERM) ---" << std::endl;
            raise(SIGTERM);
            break;
    }

    return 0;  // Normal return: also calls atexit functions
}

VI. Advanced Signal Handling Techniques

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <cstring>
#include <unistd.h>

// ===== Technique 1: use write() for debug output in a signal handler =====
volatile sig_atomic_t exitFlag = 0;

void safeHandler(int signum) {
    // Build the message (do not use std::string -- it is unsafe)
    char msg[64];
    int len = snprintf(msg, sizeof(msg),
                       "Signal %d caught (PID=%d)\n",
                       signum, getpid());
    write(STDOUT_FILENO, msg, len);

    exitFlag = signum;  // Store the signal number
}

// ===== Technique 2: Graceful Shutdown pattern =====
class Application {
public:
    void run() {
        signal(SIGINT, safeHandler);
        signal(SIGTERM, safeHandler);

        std::cout << "Application started (PID=" << getpid() << ")" << std::endl;

        int cycle = 0;
        while (!exitFlag) {
            // Simulate work
            std::cout << "Running... cycle " << ++cycle << std::endl;
            sleep(1);
        }

        // Outside the signal handler, any C++ feature can be used safely
        std::cout << "\nReceived signal " << static_cast<int>(exitFlag)
                  << ", starting graceful shutdown..." << std::endl;
        cleanup();
    }

private:
    void cleanup() {
        // std::cout, std::string, etc. can be used safely here
        std::cout << "  [1/3] Saving state..." << std::endl;
        sleep(1);
        std::cout << "  [2/3] Closing connections..." << std::endl;
        sleep(1);
        std::cout << "  [3/3] Releasing resources..." << std::endl;
        std::cout << "Graceful shutdown complete" << std::endl;
    }
};

int main() {
    Application app;
    std::cout << "Press Ctrl+C to test graceful shutdown..." << std::endl;
    app.run();
    return 0;
}

VII. Signals and Daemonization

   When turning a process into a daemon, signal handling is a key step. A daemon
   must correctly handle SIGHUP, SIGTERM, and SIGCHLD:

   ---------------------------------------------------------------
   #include <iostream>
   #include <csignal>
   #include <cstring>
   #include <unistd.h>
   #include <sys/stat.h>
   #include <fcntl.h>

   volatile sig_atomic_t daemonRunning = 1;

   void daemonSigHandler(int sig) {
       write(STDOUT_FILENO, "[Daemon] Signal\n", 16);
       if (sig == SIGTERM || sig == SIGINT) daemonRunning = 0;
   }

   // Standard steps to become a daemon
   bool daemonize() {
       // 1. fork a child and exit the parent (the child becomes an orphan)
       pid_t pid = fork();
       if (pid < 0) return false;
       if (pid > 0) _Exit(0);  // Parent exits

       // 2. The child creates a new session (detaches from the terminal)
       if (setsid() < 0) return false;

       // 3. Ignore SIGHUP and fork again (ensure we are not the session leader)
       signal(SIGHUP, SIG_IGN);
       pid = fork();
       if (pid < 0) return false;
       if (pid > 0) _Exit(0);

       // 4. Change the working directory to root
       chdir("/");

       // 5. Reset the file mode creation mask
       umask(0);

       // 6. Close the standard file descriptors
       close(STDIN_FILENO);
       close(STDOUT_FILENO);
       close(STDERR_FILENO);

       // 7. Redirect them to /dev/null
       open("/dev/null", O_RDONLY);  // stdin
       open("/dev/null", O_WRONLY);  // stdout
       open("/dev/null", O_WRONLY);  // stderr

       return true;
   }

   int main() {
       std::cout << "Becoming a daemon..." << std::endl;

       if (!daemonize()) {
           std::cerr << "Daemonization failed" << std::endl;
           return 1;
       }

       // We are now detached from the terminal; cout/cerr no longer reach the screen
       // You must use syslog or write to a log file

       signal(SIGTERM, daemonSigHandler);
       signal(SIGINT, daemonSigHandler);

       // Daemon main loop
       while (daemonRunning) {
           // Real work...
           sleep(5);
       }

       return 0;
   }
   ---------------------------------------------------------------

   Key points of daemon signal handling:
   - SIGHUP: traditionally used to tell a daemon to reload its configuration file
   - SIGTERM: the graceful termination signal
   - SIGUSR1/SIGUSR2: used for custom notifications (e.g. toggling debug mode)
   - A daemon has no terminal, so cout cannot be used; use syslog or a log file

VIII. Cross-Platform Signal Handling Considerations

   C++ signal handling differs between platforms:

   ┌──────────────┬─────────────────┬───────────────────────────────┐
   │ Platform     │ <csignal>       │ Extensions                    │
   ├──────────────┼─────────────────┼───────────────────────────────┤
   │ Linux        │ Full support    │ sigaction, signalfd, timerfd  │
   │ macOS        │ Full support    │ BSD-based, some differences   │
   │ Windows      │ Limited support │ SIGINT/SIGTERM available      │
   │              │                 │ No SIGUSR1/SIGUSR2/SIGHUP     │
   │              │                 │ Windows: SetConsoleCtrlHandler│
   └──────────────┴─────────────────┴───────────────────────────────┘

   The Windows equivalent of SIGINT handling:

   ---------------------------------------------------------------
   #ifdef _WIN32

           std::cout << "Ctrl+C pressed" << std::endl;

       if (signal == CTRL_CLOSE_EVENT) {
           std::cout << "Console window closing" << std::endl;

       }

   }

   int main() {
       SetConsoleCtrlHandler(consoleHandler, TRUE);
       // ...
   }
   #endif

   Cross-platform best practices:
   - Prefer SIGINT/SIGTERM (cross-platform compatible)
   - Put platform-specific code inside #ifdef blocks
   - Consider third-party libraries (e.g. boost::asio signal handling)

Example 1: A Server with Graceful Shutdown -- Smoothly Stopping a Web Server
---------------------------------------------------------------
Scenario: when a web server receives a termination signal, it should not exit
immediately; it should finish the requests currently being processed, close
files, and release connections before shutting down gracefully.

Knowledge integrated:
- Ch3 Dynamic memory/smart pointers: unique_ptr manages connections
- Ch9 Exception handling: exception safety after signal handling
- Ch10 File operations: logging
- This chapter: signal() + sig_atomic_t

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <cstring>
#include <unistd.h>
#include <vector>
#include <memory>
#include <fstream>
#include <chrono>
#include <iomanip>

// Signal flags
volatile sig_atomic_t g_shutdownRequested = 0;
volatile sig_atomic_t g_reloadRequested = 0;

void serverSignalHandler(int signum) {
    char msg[64];
    int len = snprintf(msg, sizeof(msg),
                       "[signal] Received signal %d\n", signum);
    write(STDOUT_FILENO, msg, len);

    switch (signum) {
        case SIGINT:
        case SIGTERM:
            g_shutdownRequested = 1;
            break;
        case SIGHUP:
            g_reloadRequested = 1;
            break;
    }
}

// Simulated client connection (Ch3 smart pointers)
class ClientConnection {
private:
    int clientId;
    bool connected;
public:
    ClientConnection(int id) : clientId(id), connected(true) {
        std::cout << "  [connect] Client #" << clientId << " connected" << std::endl;
    }

    ~ClientConnection() noexcept {
        if (connected) {
            std::cout << "  [disconnect] Client #" << clientId << " disconnected" << std::endl;
        }
    }

    void process() {
        if (!connected) return;
        std::cout << "  [process] Client #" << clientId << " request in progress..." << std::endl;
        usleep(300000);  // Simulate processing time
    }

    void disconnect() {
        connected = false;
    }

    int getId() const { return clientId; }
    bool isConnected() const { return connected; }
};

// Logger (Ch10 file operations)
class ServerLogger {
private:
    std::ofstream logFile;
public:
    ServerLogger(const std::string& filename) {
        logFile.open(filename, std::ios::app);
    }

    ~ServerLogger() {
        if (logFile.is_open()) logFile.close();
    }

    void log(const std::string& level, const std::string& msg) {
        auto now = std::chrono::system_clock::now();
        auto timeT = std::chrono::system_clock::to_time_t(now);

        logFile << "[" << std::put_time(std::localtime(&timeT),
                                         "%Y-%m-%d %H:%M:%S") << "]"
                << "[" << level << "] " << msg << std::endl;
        logFile.flush();

        // Also print to the console
        std::cout << "[" << level << "] " << msg << std::endl;
    }
};

// Main server class
class WebServer {
private:
    std::vector<std::unique_ptr<ClientConnection>> connections;
    std::unique_ptr<ServerLogger> logger;
    bool running;

public:
    WebServer() : running(false) {
        logger = std::make_unique<ServerLogger>("server.log");
    }

    void start() {
        running = true;
        logger->log("INFO", "Server started (PID=" + std::to_string(getpid()) + ")");

        // Register signal handlers
        signal(SIGINT, serverSignalHandler);
        signal(SIGTERM, serverSignalHandler);
        signal(SIGHUP, serverSignalHandler);

        // Simulate accepting connections
        int connectionCounter = 0;
        int tick = 0;

        while (running) {
            // Check signals
            if (g_reloadRequested) {
                g_reloadRequested = 0;
                logger->log("INFO", "Reloading configuration file...");
            }

            if (g_shutdownRequested) {
                logger->log("WARN", "Shutdown signal received, preparing graceful exit...");
                running = false;
                break;  // Leave the main loop and run cleanup
            }

            // Simulate periodic work
            tick++;
            if (tick % 3 == 0) {
                // Accept a new connection
                connectionCounter++;
                auto conn = std::make_unique<ClientConnection>(connectionCounter);
                connections.push_back(std::move(conn));
                logger->log("INFO", "New connection: client #"
                            + std::to_string(connectionCounter));
            }

            // Process existing connections
            for (auto& conn : connections) {
                if (conn->isConnected()) {
                    conn->process();
                }
            }

            // Remove disconnected connections
            connections.erase(
                std::remove_if(connections.begin(), connections.end(),
                    [](const auto& conn) { return !conn->isConnected(); }),
                connections.end()
            );

            usleep(500000);  // 500ms main loop interval
        }

        shutdown();
    }

private:
    void shutdown() {
        logger->log("INFO", "Starting graceful shutdown...");

        // 1. Finish all in-flight requests
        logger->log("INFO", "Waiting for " + std::to_string(connections.size())
                    + " connections to finish...");
        for (auto& conn : connections) {
            if (conn->isConnected()) {
                logger->log("INFO", "Closing client #"
                            + std::to_string(conn->getId()));
                conn->disconnect();
            }
        }
        connections.clear();

        // 2. Flush the log
        logger->log("INFO", "Server shut down safely");

        // 3. RAII automatically releases logger and connections
        std::cout << "\nServer exit complete" << std::endl;
    }
};

int main() {
    std::cout << "===== Web Server Graceful Shutdown Demo =====" << std::endl;
    std::cout << "The server will run for about 10 seconds, then automatically receive a shutdown signal" << std::endl;
    std::cout << "You can also press Ctrl+C to trigger shutdown manually" << std::endl << std::endl;

    // Simulate sending a shutdown signal on a timer from another process
    // (demo only; in practice it is triggered externally by kill/Ctrl+C)
    WebServer server;

    // Simulate sending the shutdown signal after 5 seconds
    // fork a child process to send the signal
    pid_t parentPid = getpid();
    pid_t child = fork();

    if (child == 0) {
        // Child process: wait, then send the signal
        sleep(5);
        kill(parentPid, SIGTERM);
        _Exit(0);
    } else {
        // Parent process: run the server
        server.start();
    }

    // Remove the log file
    std::remove("server.log");

    return 0;
}

Example 1 Supplement: Advanced Patterns Combining Signals with RAII

In real C++ projects, signal handling is not just about setting flags; it must
also be combined with the RAII pattern to guarantee that resources are still
released correctly after a signal fires. Here are several common patterns:

Pattern A: Signal-Safe Resource Handle (FileDescriptor RAII)

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <cstring>
#include <unistd.h>
#include <fcntl.h>

// RAII wrapper for a signal-safe file descriptor
class SafeFileDescriptor {
private:
    int fd;
public:
    SafeFileDescriptor(const char* path, int flags) : fd(-1) {
        fd = open(path, flags, 0644);  // open() is async-signal-safe
    }

    ~SafeFileDescriptor() {
        if (fd >= 0) close(fd);  // close() is async-signal-safe
    }

    int get() const { return fd; }
    bool valid() const { return fd >= 0; }

    // Non-copyable, movable
    SafeFileDescriptor(const SafeFileDescriptor&) = delete;
    SafeFileDescriptor& operator=(const SafeFileDescriptor&) = delete;
    SafeFileDescriptor(SafeFileDescriptor&& other) noexcept
        : fd(other.fd) { other.fd = -1; }
};

volatile sig_atomic_t emergencySave = 0;

void emergencyHandler(int sig) {
    emergencySave = 1;
}

void emergencyWriteLog() {
    // Signal-safe log writing
    static SafeFileDescriptor logFd("/tmp/emergency.log",
        O_WRONLY | O_CREAT | O_APPEND);

    if (logFd.valid()) {
        const char* msg = "Emergency save triggered\n";
        write(logFd.get(), msg, strlen(msg));
    }
}

int main() {
    signal(SIGTERM, emergencyHandler);
    signal(SIGINT, emergencyHandler);

    std::cout << "Main loop running (PID=" << getpid() << ")..." << std::endl;

    for (int i = 0; i < 20; i++) {
        if (emergencySave) {
            emergencySave = 0;
            emergencyWriteLog();
            std::cout << "[main thread] Emergency log written" << std::endl;
        }
        sleep(1);
    }

    std::remove("/tmp/emergency.log");
    return 0;
}

Pattern B: A Signal-Driven Graceful Shutdown Queue

Turn the signal into "shutdown tasks" in a task queue and run the cleanup in
order on the main thread:

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <vector>
#include <functional>
#include <string>

volatile sig_atomic_t shutdownSignal = 0;

void shutdownHandler(int sig) {
    shutdownSignal = 1;
}

// A cleanup task run at shutdown
class CleanupTask {
public:
    using TaskFunc = std::function<void()>;
private:
    std::string name;
    TaskFunc func;
public:
    CleanupTask(const std::string& n, TaskFunc f)
        : name(n), func(std::move(f)) {}

    void execute() {
        std::cout << "[cleanup] " << name << "..." << std::endl;
        func();
    }
};

int main() {
    signal(SIGTERM, shutdownHandler);
    signal(SIGINT, shutdownHandler);

    // Register the cleanup task queue
    std::vector<CleanupTask> cleanupTasks;
    cleanupTasks.emplace_back("Save user data", []() {
        std::cout << "  Simulating saving data to disk..." << std::endl;
        sleep(1);
    });
    cleanupTasks.emplace_back("Close network connections", []() {
        std::cout << "  Simulating sending disconnect packets..." << std::endl;
        sleep(1);
    });
    cleanupTasks.emplace_back("Flush log buffers", []() {
        std::cout << "  Simulating a forced log flush..." << std::endl;
    });
    cleanupTasks.emplace_back("Delete PID file", []() {
        std::cout << "  Deleting /tmp/app.pid..." << std::endl;
    });

    std::cout << "Application running (PID=" << getpid()
              << "), send SIGTERM to trigger graceful shutdown" << std::endl;

    int tick = 0;
    while (!shutdownSignal && tick < 30) {
        std::cout << "  [running] tick=" << ++tick << std::endl;
        sleep(1);
    }

    // Run the cleanup queue (in reverse order, like stack unwinding)
    std::cout << "\nStarting graceful shutdown..." << std::endl;
    for (auto it = cleanupTasks.rbegin();
         it != cleanupTasks.rend(); ++it) {
        it->execute();
    }

    std::cout << "Graceful shutdown complete" << std::endl;
    return 0;
}
--------------------------------------------------------------

These patterns show how to combine the low-level signal mechanism with the
high-level RAII pattern in C++, keeping signal handling safe while gaining the
convenience of C++ RAII.

#include <iostream>
#include <csignal>
#include <cstring>
#include <unistd.h>
#include <fstream>
#include <sstream>
#include <vector>
#include <string>

// Signal-safe flags (only set flags; do nothing complex)
volatile sig_atomic_t g_saveRequested = 0;
volatile sig_atomic_t g_terminateRequested = 0;

void editorSignalHandler(int signum) {
    char msg[64];
    int len = snprintf(msg, sizeof(msg),
                       "\n[editor] Received signal %d\n", signum);
    write(STDOUT_FILENO, msg, len);

    switch (signum) {
        case SIGTERM:
        case SIGINT:
            g_saveRequested = 1;      // Request a save
            g_terminateRequested = 1;  // Request exit
            break;
        case SIGUSR1:
            g_saveRequested = 1;      // Request a save only (do not exit)
            break;

// Text buffer
class TextBuffer {
private:
    std::vector<std::string> lines;
    std::string filename;
    bool modified;

public:
    TextBuffer(const std::string& fname = "untitled.txt")
        : filename(fname), modified(false) {}

    void insertLine(int lineNum, const std::string& text) {
        if (lineNum < 0 || lineNum > static_cast<int>(lines.size())) {
            lines.push_back(text);
        } else {
            lines.insert(lines.begin() + lineNum, text);
        }
        modified = true;
    }

    void deleteLine(int lineNum) {
        if (lineNum >= 0 && lineNum < static_cast<int>(lines.size())) {
            lines.erase(lines.begin() + lineNum);
            modified = true;
        }
    }

    void display() const {
        std::cout << "===== " << filename << " ("
                  << lines.size() << " lines";
        if (modified) std::cout << " *modified*";
        std::cout << ") =====" << std::endl;

        for (size_t i = 0; i < lines.size(); ++i) {
            std::cout << i + 1 << ": " << lines[i] << std::endl;
        }
    }

    // Save to a file
    bool save(const std::string& savePath = "") {
        std::string path = savePath.empty() ? filename : savePath;
        std::ofstream file(path);
        if (!file.is_open()) {
            return false;
        }

        for (const auto& line : lines) {
            file << line << "\n";
        }
        file.close();

        modified = false;
        std::cout << "[save] " << lines.size() << " lines saved to "
                  << path << std::endl;
        return true;
    }

    // Save an auto-recovery file (called by the main loop after a signal fires)
    void autoSave() {
        if (!modified) return;

        std::ostringstream autosaveName;
        autosaveName << filename << ".autosave."
                     << time(nullptr);

        if (save(autosaveName.str())) {
            std::cout << "[auto-save] Emergency save complete: "
                      << autosaveName.str() << std::endl;

            // Clean up old auto-save files (keep only the newest)
            // A real application should do this cleanup
        }
    }

    // Check whether an auto-save recovery file exists

        // Simplified implementation: should really scan the directory

        return test.good();

    bool isModified() const { return modified; }

};

// Main editor class
class TextEditor {
private:
    std::unique_ptr<TextBuffer> buffer;
    bool running;

    // Simulate user editing
    void simulateEditing() {
        buffer->insertLine(-1, "#include <iostream>");
        buffer->insertLine(-1, "");
        buffer->insertLine(-1, "int main() {");
        buffer->insertLine(-1, "    std::cout << \"Signal handling demo\" << std::endl;");
        buffer->insertLine(-1, "    return 0;");
        buffer->insertLine(-1, "}");
    }

    // Simulate continuous editing
    void continuousEditing() {
        static int counter = 0;
        counter++;
        if (counter % 3 == 0) {
            std::ostringstream oss;
            oss << "    // Edit #" << counter;
            buffer->insertLine(-1, oss.str());
        }
    }

public:
    TextEditor(const std::string& filename)
        : running(false) {
        buffer = std::make_unique<TextBuffer>(filename);
    }

    void run() {
        running = true;

        // Register signal handlers
        signal(SIGTERM, editorSignalHandler);
        signal(SIGINT, editorSignalHandler);
        signal(SIGUSR1, editorSignalHandler);

        // Check whether an auto-save recovery file exists
        if (TextBuffer::hasAutoSave(buffer->getFilename())) {
            std::cout << "[startup] Auto-save file found, restore? (demo: skipped automatically)"
                      << std::endl;
        }

        // Initial editing
        simulateEditing();
        buffer->display();

        std::cout << "\n--- Editor running ---" << std::endl;
        std::cout << "  * Use kill -TERM <PID> or kill -USR1 <PID> to trigger" << std::endl;
        std::cout << "  auto-save" << std::endl;
        std::cout << "  * PID: " << getpid() << std::endl;
        std::cout << "  * The main loop checks signal flags every second" << std::endl << std::endl;

        int tick = 0;
        while (running) {
            // Check signal flags (handled safely in the main loop)
            if (g_saveRequested) {
                g_saveRequested = 0;
                buffer->autoSave();  // Saving in the main loop -- safe
            }

            if (g_terminateRequested) {
                g_terminateRequested = 0;
                std::cout << "\n[editor] Termination signal received, auto-saving before exit..."
                          << std::endl;
                buffer->autoSave();
                running = false;
                break;

            // Simulate continuous editing
            continuousEditing();

            tick++;
            if (tick % 5 == 0) {
                buffer->display();
            }

            sleep(1);
        }

        std::cout << "\nEditor exited. On next startup, the .autosave file can be detected for recovery."
                  << std::endl;
    }

Example 3: Daemon Signal Management -- A Linux Background Service
---------------------------------------------------------------
Scenario: a Linux daemon must handle several signals:
SIGHUP (reload config), SIGTERM (graceful exit), SIGUSR1 (print status).

Knowledge integrated:
- Ch1 Namespaces: namespace DaemonLib {}
- Ch3 Smart pointers: unique_ptr
- Ch8 Templates: template functions to register signals
- Ch9 Exception handling: safe exit
- Ch10 File operations: PID file, logging

---------------------------------------------------------------
#include <iostream>
#include <csignal>
#include <cstring>
#include <unistd.h>
#include <fstream>
#include <sstream>
#include <memory>
#include <vector>
#include <map>
#include <functional>
#include <filesystem>
#include <ctime>
#include <sys/stat.h>

namespace fs = std::filesystem;

namespace DaemonLib {

    // Signal-safe flags (assignment only; nothing complex)
    volatile sig_atomic_t g_reloadConfig = 0;
    volatile sig_atomic_t g_printStatus = 0;
    volatile sig_atomic_t g_shutdown = 0;
    volatile sig_atomic_t g_lastSignal = 0;

    // Signal-safe handler
    void daemonSignalHandler(int signum) {
        g_lastSignal = signum;

        switch (signum) {
            case SIGHUP:
                g_reloadConfig = 1;
                break;
            case SIGUSR1:
                g_printStatus = 1;
                break;
            case SIGINT:
            case SIGTERM:
                g_shutdown = 1;
                break;
            case SIGUSR2:
                // Reserved signal
                break;
        }
    }

    // Signal registrar (template version)
    template<int Signal>
    struct SignalRegistrar {
        static void registerSignal() {
            signal(Signal, daemonSignalHandler);
        }
    };

    // ===== Daemon configuration =====
    struct DaemonConfig {
        std::string name;
        std::string pidFile;
        std::string logFile;
        std::string dataDir;
        int checkInterval;  // seconds
        bool verbose;

        DaemonConfig()
            : name("mydaemon"),
              pidFile("/tmp/mydaemon.pid"),
              logFile("/tmp/mydaemon.log"),
              dataDir("/tmp/mydaemon_data"),
              checkInterval(5),
              verbose(false) {}

        void reload() {
            std::cout << "[config] Reloading configuration" << std::endl;
            // In practice, read from the config file
        }
    };

    // ===== Log manager (Ch10 file operations) =====
    class DaemonLogger {
    private:
        std::ofstream logStream;
        std::string logFilePath;

        std::string timestamp() const {
            time_t now = time(nullptr);
            char buf[64];
            strftime(buf, sizeof(buf), "%Y-%m-%d %H:%M:%S",
                     localtime(&now));
            return std::string(buf);
        }

    public:
        DaemonLogger(const std::string& path) : logFilePath(path) {
            logStream.open(path, std::ios::app);
        }

        ~DaemonLogger() {
            if (logStream.is_open()) logStream.close();
        }

        void info(const std::string& msg) {
            logStream << "[" << timestamp() << "] [INFO] "
                      << msg << std::endl;
            std::cout << "[INFO] " << msg << std::endl;
            logStream.flush();
        }

        void warn(const std::string& msg) {
            logStream << "[" << timestamp() << "] [WARN] "
                      << msg << std::endl;
            std::cout << "[WARN] " << msg << std::endl;
            logStream.flush();
        }

        void error(const std::string& msg) {
            logStream << "[" << timestamp() << "] [ERROR] "
                      << msg << std::endl;
            std::cerr << "[ERROR] " << msg << std::endl;
            logStream.flush();
        }
    };

    // ===== PID file management (Ch10 filesystem) =====
    class PIDFile {
    private:
        std::string path;

    public:
        PIDFile(const std::string& p) : path(p) {}

        bool create() {
            // Make sure the parent directory exists
            fs::path parent = fs::path(path).parent_path();
            if (!parent.empty() && !fs::exists(parent)) {
                fs::create_directories(parent);
            }

            std::ofstream file(path);
            if (!file.is_open()) return false;

            file << getpid() << std::endl;
            file.close();

            // Set permissions
            chmod(path.c_str(), 0644);

            return true;
        }

        void remove() {
            std::remove(path.c_str());
        }

        static int readPID(const std::string& path) {
            std::ifstream file(path);
            if (!file.is_open()) return -1;

            int pid;
            file >> pid;
            return pid;
        }
    };

    // ===== Core daemon class =====
    class Daemon {
    private:
        DaemonConfig config;
        std::unique_ptr<DaemonLogger> logger;
        std::unique_ptr<PIDFile> pidFile;
        int tickCount;
        bool running;

        // Do the work task (subclasses may override)
        virtual void doWork() {
            tickCount++;
            if (tickCount % 10 == 0) {
                logger->info("Running periodic task (tick " +
                             std::to_string(tickCount) + ")");
            }

            // Simulation: check the data directory
            if (!fs::exists(config.dataDir)) {
                fs::create_directory(config.dataDir);
                logger->info("Created data directory: " + config.dataDir);
            }
        }

        // Print the running status
        virtual void printStatus() {
            std::cout << "\n===== Daemon Status =====" << std::endl;
            std::cout << "  Name:    " << config.name << std::endl;
            std::cout << "  PID:     " << getpid() << std::endl;
            std::cout << "  Running: " << tickCount << " cycles" << std::endl;
            std::cout << "  Config:  check interval=" << config.checkInterval
                      << "s" << std::endl;
            std::cout << "  Data dir: " << config.dataDir << std::endl;
            std::cout << "==========================" << std::endl;

            logger->info("Status report: " + std::to_string(tickCount)
                         + " cycles executed");
        }

        // Reload configuration
        virtual void reloadConfig() {
            config.reload();
            logger->info("Configuration reload complete");
        }

        // Register all signals
        void registerSignals() {
            SignalRegistrar<SIGHUP>::registerSignal();
            SignalRegistrar<SIGINT>::registerSignal();
            SignalRegistrar<SIGTERM>::registerSignal();
            SignalRegistrar<SIGUSR1>::registerSignal();
            SignalRegistrar<SIGUSR2>::registerSignal();

            // Ignore some signals we don't need to handle
            signal(SIGPIPE, SIG_IGN);
            signal(SIGCHLD, SIG_IGN);
        }

    public:
        Daemon(const DaemonConfig& cfg)
            : config(cfg), tickCount(0), running(false) {}

        virtual ~Daemon() {
            if (pidFile) {
                pidFile->remove();
            }
        }

        int start() {
            // 1. Initialize logging
            logger = std::make_unique<DaemonLogger>(config.logFile);
            logger->info("Daemon starting: " + config.name);

            // 2. Create the PID file
            pidFile = std::make_unique<PIDFile>(config.pidFile);
            if (!pidFile->create()) {
                logger->error("Cannot create PID file: " + config.pidFile);
                return 1;
            }
            logger->info("PID file: " + config.pidFile + " (PID="
                         + std::to_string(getpid()) + ")");

            // 3. Register signals
            registerSignals();
            logger->info("Signal handlers registered");

            // 4. Make sure the data directory exists
            if (!fs::exists(config.dataDir)) {
                fs::create_directories(config.dataDir);
            }

            // 5. Main loop
            running = true;
            while (running) {
                // === Signal handling (in the main loop, C++ features are safe) ===

                if (g_reloadConfig) {
                    g_reloadConfig = 0;
                    reloadConfig();
                }

                if (g_printStatus) {
                    g_printStatus = 0;
                    printStatus();
                }

                if (g_shutdown) {
                    g_shutdown = 0;
                    logger->info("Shutdown signal received, preparing to exit...");
                    running = false;
                    break;
                }

                // Do the work task
                doWork();

                // Sleep (simulated with sleep; in practice use select/epoll)
                sleep(config.checkInterval);
            }

            // 6. Clean up and exit
            shutdown();
            return 0;
        }

        virtual void shutdown() {
            logger->info("Running exit cleanup...");

            // Subclasses can override this for additional cleanup
            // e.g. closing database connections, notifying other services, etc.

            logger->info("Daemon exited safely");

            // The PID file is removed automatically in the destructor
        }
    };

} // namespace DaemonLib

class DataCollectorDaemon : public DaemonLib::Daemon {
private:
    std::vector<double> dataPoints;

protected:
    void doWork() override {
        // Simulate data collection
        double sample = static_cast<double>(rand()) / RAND_MAX * 100.0;
        dataPoints.push_back(sample);
        if (dataPoints.size() > 100) {
            dataPoints.erase(dataPoints.begin());
        }

        // Periodic report
        static int subTick = 0;
        subTick++;
        if (subTick % 3 == 0) {
            double avg = 0;
            for (double d : dataPoints) avg += d;
            avg /= dataPoints.size();

            std::cout << "[collect] samples=" << dataPoints.size()
                      << " average=" << avg << std::endl;
        }
    }

    void printStatus() override {
        DaemonLib::Daemon::printStatus();  // Call the base class
        std::cout << "  Data points: " << dataPoints.size() << std::endl;
    }
};

    DataCollectorDaemon daemon(config);

    pid_t ppid = getpid();
    pid_t child = fork();

    if (child == 0) {
        // Child process: send signals on a schedule
        sleep(4);
        std::cout << "\n[simulate] Sending SIGUSR1 (print status)" << std::endl;
        kill(ppid, SIGUSR1);

        sleep(4);
        std::cout << "\n[simulate] Sending SIGHUP (reload config)" << std::endl;
        kill(ppid, SIGHUP);

        sleep(4);
        std::cout << "\n[simulate] Sending SIGTERM (graceful exit)" << std::endl;
        kill(ppid, SIGTERM);

        _Exit(0);
    } else {
        daemon.start();
    }

    // Cleanup
    std::remove("/tmp/datacollector.pid");
    std::remove("/tmp/datacollector.log");
    fs::remove_all("/tmp/datacollector_data");

    return 0;

[Golden Rules of Signal Handling Programming -- Chapter Summary]

  Rule 1: Do as little as possible in a signal handler -- set a volatile sig_atomic_t flag

  Rule 2: Put all complex logic in the main loop/main thread, triggered by checking flags

  Rule 3: Only call "async-signal-safe" functions in a signal handler
          (write, close, open, _exit, signal, kill, etc.)

  Rule 4: Manage resources with RAII so they are released correctly even when a signal arrives

  Rule 5: SIGKILL and SIGSTOP cannot be caught, ignored, or blocked

  Rule 6: After catching SIGSEGV/SIGABRT/SIGFPE, do not try to recover; just write an emergency log and exit

  Rule 7: When reliable signal handling is needed, use POSIX sigaction instead of signal

  Rule 8: In cross-platform development, put platform-specific signal code in #ifdef blocks

  Rule 9: A daemon must correctly handle SIGHUP (reload config) and SIGTERM (graceful exit)

  Rule 10: Never throw a C++ exception from a signal handler
